## 1. 回写方式：增量修订，不全文重生成

- ReviewAgent 根据 EvalRunner 的**失败证据**定位 `knowledge_path`，**只修订受影响知识**
- 修订的同时对**关联段落做一致性检查**（避免修 A 段破坏 B 段的引用/定义）
- 依据 01：修订阶段按 knowledge_path 检索定位，只取命中段落，不重读全文

## 2. 版本治理：KnowledgeStore 是生命周期组件，不是"存 Markdown"

每轮生成新的 **Knowledge Version**，由 KnowledgeStore 管理：

- current version
- historical best version
- verification score
- 状态：verified / low-confidence / human-review 等
- 对应 Eval / Review / source provenance / version lineage

## 3. Verification Score（不用 LLM 自评，也不简单等于 Pass Rate）

两条禁令：

- ❌ 不允许 LLM 自己给"置信度"打分
- ❌ 不允许简单定义 `confidence = test pass rate`

正确做法：使用 **Verification Score / Knowledge Quality Score**。Pass Rate 是重要输入，但必须结合：

- critical behavior gate（关键行为门禁）
- test pass rate
- coverage / mutation score（可获得时）
- provenance 完整度
- CheckAgent 严重问题
- 跨轮稳定性

**Critical Gate 失败时，即使整体 Pass Rate 很高也不得 verified。**

## 4. 迭代预算：maxIterations ≤ 5 是工程值，不是黄金数字

- V1 默认 `maxIterations <= 5`
- **明确**：5 是工程初始值与安全上限，**不是论文证明的"黄金数字"**，后续根据本项目真实实验数据调整
- 论文证据（TDD-Agent 2026，arXiv:2608.16742）：第 5 轮时 TDD-Agent 已 "surpasses the mini-SWE-agent baseline by its fifth iteration"，但**继续增加迭代仍有性能收益**；不同模型的提升曲线大约 "reach a near-plateau around iterations 6–7"，后续收益是 diminishing returns。更准确的结论是**"迭代存在边际收益递减"**，而不是"5 轮具有理论最优性"

## 5. Early Stop + Rollback

- **始终保留 historical best version**
- 出现 **critical regression** → 立即放弃当前版本，回滚到 best version
- 连续若干轮无显著 improvement → 提前停止
- regression / stagnation 的**具体阈值作为可配置参数**，不写死 5%、2% 之类未经本项目实验验证的数值

## 6. 未达标转人工：LOW_CONFIDENCE + Human Governance Package

达到最大迭代次数或提前停滞仍未达标：

- 标记 **LOW_CONFIDENCE**
- 转**人工治理**
- 提供 **Human Governance Package**：
  - failed cases（expected vs actual）
  - regression cases
  - ReviewAgent 的 knowledge_path / weak_spots / corrections
  - historical best knowledge version
  - knowledge diff
  - source provenance
  - unresolved risks

## 7. 人工修订 ≠ verified：仍须重走全流程

人工修订后**不能直接标记 verified**，必须重新执行：

```
Knowledge → CodeAgent fresh generation → EvalRunner → Gate
```

通过后才升级为 **VERIFIED**。

## 8. 跨轮比较：稳定 Core Gate Test Set

- 跨轮比较**尽量使用稳定的 Core Gate Test Set**
- 新增测试进入 **Candidate / Expanded Test Set**
- 避免因测试集每轮变化导致不同轮次 Pass Rate 不可直接比较

## 9. 论文证据（2025+）

| 论文 | 支持哪条规则 | 关键结论 | 链接 |
|---|---|---|---|
| TDD-Agent（2026.08） | §4 迭代预算 | "surpasses the mini-SWE-agent baseline by its fifth iteration"，但 6–7 轮才 near-plateau，后续 diminishing returns → 5 是工程值不是最优 | https://arxiv.org/abs/2608.16742 |
| TDD-Agent（2026.08） | §3 不把 pass rate 当置信度 | "internally consistent but incomplete state"：生成代码通过了自己生成的测试，却仍失败于 held-out repository tests → 测试与代码可能共同漏掉真实行为 | https://arxiv.org/abs/2608.16742 |

**结论**：迭代存在边际收益递减（不是"5 轮最优"）；测试通过率不能直接等同于知识置信度（测试与代码可能共同漏掉真实行为）。`maxIterations = 5` 是 V1 的工程预算与安全上限，后续根据本项目迭代收益曲线校准。
