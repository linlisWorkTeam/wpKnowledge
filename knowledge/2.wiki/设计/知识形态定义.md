# 知识形态定义（Knowledge Format）

> 最后更新：2026-08-20

## 1. 核心定义

知识形态为**纯 Markdown 文档**：基于代码仓源码反推出的知识文档。

## 2. 文档内容构成

一份知识文档包含两类内容：

### 2.1 代码示例

- 包含**部分源代码片段**（片段级，非全文搬运）。
- 保留源码中有价值的实现细节。

### 2.2 代码解释与抽象

对代码进行**解释和抽象**，包括：

- **编写原因**：这段代码为什么要这样写。
- **解决的问题**：它为了解决什么问题。
- **实现思路**：背后的实现思路是什么。
- **设计逻辑**：代码背后的设计决策与权衡。
- **适用场景**：在什么场景下应该采用这样的写法。

## 3. 关键原则

> 知识文档给出代码的同时，解释代码背后的知识与逻辑，而非把一整段源代码直接搬进文档、把源码本身当成知识。

| ✅ 知识文档应该 | ❌ 知识文档不应该 |
|----------------|------------------|
| 保留有价值的实现细节 | 整段搬运源码全文 |
| 解释"为什么这样写" | 只罗列代码不解释 |
| 提炼实现思路与设计逻辑 | 重复代码仓库已有内容 |
| 说明适用场景 | 脱离上下文孤立描述 |

## 4. 一句话总结

> 以 Markdown 为载体、结合代码示例和代码解释的知识文档：
> **保留源码的"魂"（知识），而非代码的"壳"（全文）**。

## 5. 格式参考锚点：OKF（设计核心参考）

本项目知识格式以 **Google knowledge-catalog / OKF（Open Knowledge Format）** 为格式锚点（⭐8756，活跃维护；深度分析见 研究/知识格式/Knowledge Catalog与OKF知识格式.md）：

- **载体**：Markdown + YAML frontmatter
- **元数据**：sources（来源）、status（状态）、verified（验证情况）——知识天生可信、可 diff、可评审
- **组织**：知识以 Bundle（目录树 / git 仓库）为单位自包含组织

> 后续格式细化（模板 / 粒度 / 目录规范）将以 OKF 为基线对齐。

## 6. 溯源链接（sources）要求 ⭐

> 依据：[RepoDoc知识图谱驱动文档生成.md](../研究/文档生成/RepoDoc知识图谱驱动文档生成.md)（文档挂接代码单元节点，变更沿图回溯）、[知识飞轮流程设计.md §4](知识飞轮流程设计.md)（差异归因机制）。

**每段知识必须标注对应的源码位置**，这是"知道改文档哪部分"的前提：

```
知识文档 §3.2「边界处理」
  ├─ 伪代码: if input is empty: return default
  ├─ 为什么: 兼容空输入是历史需求 #452
  └─ sources: src/utils/parser.py:120-135   ← 溯源链接
```

- 粒度：文件:行 或 函数/模块级（与知识段落一一对应）
- 作用：diff 差异 → 溯源映射 → 定位需修改的文档段落（详见 [知识飞轮流程设计.md §4](知识飞轮流程设计.md)）
- 规范：frontmatter 中 `sources` 字段，与 OKF 对齐
