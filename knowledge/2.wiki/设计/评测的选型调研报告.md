## 一、评测路线（选型的总纲）

**结论 1：执行式评测是主判，表面形式只做辅助**
DS-1000 实测：表面形式分数（BLEU 类）高的模型执行分数可能垫底，"像不像"与"对不对"是两回事。
→ 决策：门禁主判 = 编译 + 测试执行（confidence），相似度只进归因报告（已落地）。
依据：[执行式评测与表面形式评测.md](../研究/评测/执行式评测与表面形式评测.md)、[CodeBLEU代码感知评测指标.md](../研究/评测/CodeBLEU代码感知评测指标.md)

**结论 2：评测集测试用例太少 = 假阳性通过**
EvalPlus 实测：ChatGPT 在 HumanEval 上 65.8%，增强后 HumanEval+ 只有 46.6%，掉了近 20 个百分点。
→ 决策：评测集必须扩充边界输入（整除/不整除、单核/多核、零长度、大数），防止"背题式高分"。
依据：[EvalPlus差分测试增强评测集.md](../研究/评测/EvalPlus差分测试增强评测集.md)

**结论 3：期望输出必须来自源码实际行为（探针）**
EvalPlus 用差分测试（ground-truth 校验候选输入）保证测试正确；我们评测集期望输出 = 探针跑真实源码（红线），同构。
→ 决策：评测集构建必须探针，禁止编造期望输出（已落地）。
依据：[EvalPlus差分测试增强评测集.md](../研究/评测/EvalPlus差分测试增强评测集.md)

## 二、评测集自身质量（选型的关键补充）

**结论 4：评测集强度用变异测试度量（mutation score）**
变异测试把源码故意改坏（变异体），看评测集能不能发现；存活变异体 = 测试盲区清单。
→ 决策（P1）：评测集构建/更新时跑变异测试，mutation score ≥ 60% 才认定合格；存活变异体转成新增用例。
依据：[变异测试与测试集质量.md](../研究/评测/变异测试与测试集质量.md)

**结论 5：覆盖率量化测试盲区**
CoverUp/CodaMosa 用覆盖率告诉 LLM"哪里没测到"；覆盖率（行/分支）是测试盲区地图。
→ 决策（P1）：用 gcov 量化评测集对被测源码的线/分支覆盖，进评测集质量报告（不进门禁主判）。
依据：[覆盖率引导测试生成.md](../研究/评测/覆盖率引导测试生成.md)

**结论 6：覆盖率高 ≠ 测试强（与变异测试互补）**
覆盖率管"测到没有"，变异测试管"测错了能不能发现"；两者是评测集质量的双指标。
→ 决策：评测集质量报告同时报覆盖率与 mutation score，双低即补测试。
依据：[覆盖率引导测试生成.md](../研究/评测/覆盖率引导测试生成.md)、[变异测试与测试集质量.md](../研究/评测/变异测试与测试集质量.md)

## 三、指标细化（在已定路线内的优化）

**结论 7：相似度升级为 AST/数据流匹配（CodeBLEU）**
difflib 文本相似度"改名即扣分、换写法即扣分"；CodeBLEU 加 AST 语法 + 数据流语义分量。
→ 决策（P1）：相似度升级为 tree-sitter AST 匹配（C++ 支持），文本分量保留；仍只进归因。
依据：[CodeBLEU代码感知评测指标.md](../研究/评测/CodeBLEU代码感知评测指标.md)

**结论 8：多候选采样提升收敛（pass@k 思路）**
pass@k = 每问题生成 n 个候选，任一通过即算过；无偏估计器避免小样本方差。
→ 决策（P1）：Coder 生成 k 个候选 → 评测集择优 → 最优者进门禁（MVP 保持 1 候选）。
依据：[Pass@k无偏评测指标.md](../研究/评测/Pass@k无偏评测指标.md)

**结论 9：重复评测稳定性要量化（方差）**
pass@k 与 Fragility 均指出生成是概率性的，单次结果有方差；重复评测取最大会掩盖不稳定。
→ 决策：重复评测由"取最大"改为"均值 ± 方差"，方差超阈值判"不稳定"走 iterate（待实现）。
依据：[Pass@k无偏评测指标.md](../研究/评测/Pass@k无偏评测指标.md)、[自进化Agent脆弱性.md](../研究/反馈闭环/自进化Agent脆弱性.md)

## 四、最新方案（2025-2026 补充调研）

**结论 10：LLM 裁判有系统性偏差，不能替代客观评测**
CodeJudgeBench 实测 26 个 LLM 裁判：顺序交换结论反转、位置偏差、自我偏好。LLM 裁判只能做"归因解释"，不能做"对错判定"。
→ 决策：Review（LLM 裁判角色）结论必须与评测报告交叉验证；禁止用 LLM 打分替代测试执行。
依据：[CodeJudgeBench-LLM裁判可靠性.md](../研究/评测/CodeJudgeBench-LLM裁判可靠性.md)

**结论 11：评测集要防"表面特征依赖"（鲁棒性维度）**
Jagged Frontier 用语义保持变换（重命名/循环改写）实测：前沿模型换写法性能骤降 = 依赖表面特征。Semantic Mutation 证明 prompt 微调也导致分数大幅波动。
→ 决策（P2）：同一知识语义的评测用例多形态化；"同知识两次生成一致性"检查；源码无害变换后测相似度（若骤降=在抄源码）。
依据：[语义等价评测与鲁棒性.md](../研究/评测/语义等价评测与鲁棒性.md)

**结论 12：评测集防污染用时间戳/轮换**
LiveCodeBench 给问题打发布时间戳，只评模型 cutoff 之后的新题，从源头免疫数据泄漏。
→ 决策（P2）：评测集用例打乱/轮换，防 Coder 记忆用例。
依据：[防污染与效率评测.md](../研究/评测/防污染与效率评测.md)

**结论 13：效率是可评测的维度（差分性能评测）**
EvalPerf 用性能敏感任务 + 大输入差分对比（候选 vs 参考耗时比），把评测从"对不对"扩展到"快不快"。
→ 决策（P2）：算子代码评测集可加耗时/内存上限断言，阈值取探针跑源码实测（红线：不编造）。
依据：[防污染与效率评测.md](../研究/评测/防污染与效率评测.md)
