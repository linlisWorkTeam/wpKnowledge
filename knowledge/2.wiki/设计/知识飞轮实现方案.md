# 知识飞轮实现方案（收敛基线，2026-08-24）

> 定位：知识飞轮的统一实现方案。以 knowledge/2.wiki 设计文档为准（[知识飞轮流程设计.md](知识飞轮流程设计.md) 角色分工、[门禁与评测机制.md](门禁与评测机制.md) 评测方法），并采纳[算子团队实现方案.md](算子团队实现方案.md)的工程机制（写保护/信息隔离/readlist）。
> 背景：endlessWpKnowledgeRunner MVP（知识卡多信号文档质量打分）被判定为**方向错误**。评测对象从"代码还原"偏离为"文档质量"。本方案收敛正确基线，后续一切实现以此为准。

## 1. 方案基线（三条不可动摇）

1. **评测对象 = 基于知识生成的代码 vs 源码（代码还原）**，不是知识卡文档质量
2. **闭环 = 源码 → 知识 → 代码 → 评测 → 归因 → 知识修改 → 再生成**，直到门禁通过或达轮次上限
3. **知识库输入，飞轮演进知识副本**；首版生成由上游负责，不在本项目范围

## 2. 多 agent 协作模式

**固定流水线 + 循环迭代 + 文件交接 + 编排层状态机**，角色之间不直接对话：

```text
源码 ──▶ 知识生成 Agent ──▶ 知识文档 ──▶ Coder Agent ──▶ 临时代码
   ▲                                                          │
   │                                                          ▼
   知识生成 Agent ◀── 修订指令 ◀── 知识飞轮(编排层) ◀── 评测闭环 + Review
```

协作规则：

- **通信 = 文件产物**：知识文档（md）、临时代码（py）、评测报告（json）、归因报告（json），物理交接、可审计、可断点续跑
- **生成与验证分离**：Coder 不验证自己输出；Review 只读，不碰知识
- **信息隔离**（借鉴案例）：每个角色独立上下文；Coder 物理上看不到源码
- **编排层是状态机**：读置信度 + 归因 → 三种决策（通过/迭代/回滚），只决策不执笔
- **写保护**（借鉴案例）：受保护路径 SHA-256 快照，角色越权修改即失败

## 3. 角色与工作流（3 个执行 agent + 1 个编排层 + 1 个评测闭环）

| 单元 | 职责 | 可修改 |
|------|------|--------|
| **知识生成 Agent**（加载知识生成 skill） | 首版：源码 → 知识文档（伪代码 + 为什么 + 溯源）；迭代：按反馈修订指定段落 | ✅ 唯一执笔者 |
| **Coder Agent** | 知识 → 临时代码；不迭代、不验证、不读源码 | ❌ |
| **Review Agent** | diff 定位 + 溯源归因 + 生成反馈（结构化 + NL） | ❌ 只读 |
| **知识飞轮**（编排层） | 读置信度 + 归因 → 决策改哪段、怎么改 | ✅ 决策权，不执笔 |
| **评测闭环**（自动化） | 编译检查 + 测试执行 + 相似度 → 置信度 | ❌ 只读 |

**每轮工作流**：

1. 知识生成 Agent 加载 skill → 读源码 → 产出知识文档（每段带 sources）
2. Coder Agent → 仅基于知识写代码
3. 评测闭环 → 生成代码 vs 源码：编译（必）+ 测试（主）+ 相似度（辅助归因）→ 置信度
4. Review Agent → 差异定位 → 溯源反查 → 归因报告（如"§3.2 缺边界处理"）
5. 知识飞轮 → 置信度 ≥ 门限 → 合并（通过）；< 门限 → 下发修订指令（改哪段）；< 上一轮 → 回滚
6. 知识生成 Agent 修订 → 再测 → 直到通过或达轮次上限

## 4. 评测方法

以[门禁与评测机制.md](门禁与评测机制.md)（多信号、测试优先）为准：

- **信号组合（优先级）**：
  1. 编译 / 静态分析：必过门槛
  2. **测试执行通过率**：主信号（用例集驱动，置信度 = 通过用例数 / 总用例数）
  3. 相似度：辅助诊断（归因用，不做门禁主判）
- **评测集**：从源码 + 专家文档构建，期望输出必须来自源码实际行为，边界用例 ≥ 30%
- **holdout 防刷分**：评测集按模块分 train/holdout，holdout 不参与反馈，定期评估真实能力
- **变异测试**：验证评测集本身强度（注入 bug 抓不出 = 评测集太弱）
- **可靠性**：重复评测 ≥ 5 次报告均值±方差；评测集独立；防背源码（私有/变换代码）；规格定义到可执行级

## 5. 可靠性约束

- **防作弊**：Coder 不读源码；评测集独立；公开源码需变换
- **防污染**：未过门禁不合并；门禁分数下降自动回滚；版本控制（旧版可恢复）
- **溯源锚点**：sources 带 commit + symbol 级锚点（行号仅展示），支撑归因与代码演进
- **薄弱点地图**：某段知识反复触发差异 → 标记薄弱，优先重写
- **顺序控制**（Fragility）：知识生成顺序按依赖拓扑；对比实验固定顺序

## 6. 落地顺序

1. **P0（下一步直接做）**：评测闭环（编译 + 测试主判 + 相似度辅助）+ holdout 分层 + 修订闭环（反馈 → 归因 → 修订 → 重测）
2. **P1**：评测集构建（从源码 + 专家文档，期望输出来自源码实际行为）+ 溯源锚点升级（commit/symbol）
3. **P2**：ablation 验证（单 agent vs 多 agent、有无 Review、有无评测闭环）+ 收敛曲线报告（holdout 上画）
