## 已确认的关键决策

- **架构落地**：endlessWpKnowledgeRunner（DSH 动态插件 = 主会话，harvester = 子 agent，Python 确定性管道 = 编排/唯一执笔者）；知识卡 OKF 存储（concepts/drafts/history + index/log/ledger）；CLI + Dashboard 双入口（[知识飞轮MVP实现方案](知识飞轮MVP实现方案.md)）
- **门禁选型**：多信号加权打分（S1 溯源 0.25 / S2 结构 0.20 / S3 时效 0.10 / S4 去重 0.10 / S5 可验证 0.05 / J 陪审团 0.20 可选 / U 使用反馈 0.10），阈值默认 70，未过门禁只进 drafts；重复评测 ≥3 次报告均值±方差；相似度 80% 与测试通过率（TDD）为 roadmap 扩展，未启用
- **知识形态**：OKF 知识卡（Markdown + frontmatter：sources/status/verified/version/score），解释型文档保留逻辑"魂"，非源码搬运
- **模型约束**：仅使用公司本地部署的 GLM 5.1，经公司内部 codeagent CLI 访问
- **多 agent 不引入重型框架**：AutoGen 维护模式、LangGraph/CrewAI 不匹配固定循环 + 唯一模型 + 内网环境；自研轻量编排（确定性管道 + 脚本化决策）
- **主力路线**：源码 → 知识生成 Agent（加载知识生成 skill）产出知识 → Coder Agent 基于知识写代码 → Review Agent 对比差异 → 反馈优化（[知识飞轮流程设计](知识飞轮流程设计.md)）
- **项目边界**：本项目范围 = 飞轮演进知识副本（知识库输入，首版生成由上游负责）；背景 = 业务代码仓库（每仓几十万行），文档滞后失真，需从代码回推解释型文档
- **角色分工**：知识生成 Agent（生成知识，唯一的执笔者）/ Coder（写代码）/ Review（对比+归因+门禁）三者分离，生成与验证必须独立；知识飞轮（编排层）只决策不执笔
- **职责边界**：评测只读不修改知识；可改知识的只有知识飞轮（决策）+ 知识生成 Agent（执行）；Coder 不承担迭代逻辑
- **评测闭环**：用例集驱动——需求描述 + 知识库 → 临时代码 vs 标准代码 → 相似度 → 置信度（= f(通过的用例数)）→ 知识飞轮迭代（TDD 方案见[门禁与评测机制](门禁与评测机制.md) §7，探讨中）
- **知识修改定位**：溯源链接（sources）反向映射——diff 定位源码位置 → 映射到文档段落
- **反馈结构**：结构化信号（diff/AST/测试/相似度）+ 自然语言解读，两层结合
- **备选路线**：破坏源码 → Agent 补齐（能力补齐，非主线）
- **设计核心参考**：cannbot-knowledge（gitcode，流程锚点）+ knowledge-catalog/OKF（⭐8756，格式锚点）——OKF 定格式、cannbot 定运营流程，详见[项目概述](项目概述.md) §6
