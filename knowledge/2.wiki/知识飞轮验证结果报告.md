## 0. 一句话结论

给飞轮喂**带缺陷公式的知识文档**，飞轮用 2 轮闭环把知识修正到可用：R1 按缺陷知识生成的代码 0/8 全失败 → Review 归因定位到两个公式错误 → 下发修订指令 → 知识 v1→v2 → R2 重新生成代码 8/8 全通过 → 知识 v2 发布。全流程产物逐轮落盘，可审计、可复现。

## 2. 第 1 轮：缺陷知识 → 代码 → 全失败

### 2.1 输入：知识 v1（含缺陷）

预置文档在"算法步骤"里给出两个**错误公式**：

```text
numPerCore      = totalLength / blockNum          ← 错：应向上对齐 TILE_LENGTH=1024
tailNumLastCore = totalLength % numPerCore        ← 错：应是最后一块核的剩余长度
```

其余部分（totalTiles / tilesPerCore / blockNum 计算、边界条件）正确。该文档不含源码原文。

### 2.2 产物 A：Coder 临时代码（round_001_g001.cpp，14 行）

Coder 忠实按知识 v1 实现：

```cpp
uint32_t numPerCore = totalLength / blockNum32;
uint32_t tailNumLastCore = totalLength % numPerCore;
return {totalLength, blockNum32, numPerCore, tailNumLastCore};
```

### 2.3 产物 B：评测报告（train_round_001.json）

- 编译：通过（g++ -Wall -Werror）
- **测试：0/8 全失败**，confidence 0.00
- 重复评测：5 次 × 0/8，mean 0.00，variance 0.00，unstable false
- 相似度：0.49（仅归因诊断）
- 失败详情（节选）：

```text
FAIL tiling-default:      got blockNum=1 numPerCore=16384 tail=0, want 1/16384/16384
FAIL tiling-small:        got blockNum=1 numPerCore=100   tail=0, want 1/1024/100
FAIL tiling-big:          got blockNum=4 numPerCore=250000 tail=0, want 4/250880/247360
FAIL tiling-zero-core:    got blockNum=1 numPerCore=16384 tail=0, want 1/16384/16384
```

（8 用例全部失败：整除用例因 `totalLength % numPerCore` 得 0；非整除用例因 numPerCore 未对齐 1024。）

- 探针证据：provenance=probe，source_commit=sha256:256c…，evalset_version=unversioned
- **决策：iterate**（reason_code=TRAIN_BELOW_THRESHOLD）

### 2.4 产物 C：Review 归因报告（attribution/round_001.json）

- **summary**：`compute_tiling 中 numPerCore 与 tailNumLastCore 的计算公式错误……导致全部 8 个 tiling 用例失败`
- **weak_spots**（薄弱点地图）：
  - numPerCore 计算错误：使用 `totalLength / blockNum` 整除，未向上对齐到 TILE_LENGTH=1024
  - tailNumLastCore 计算错误：使用 `totalLength % numPerCore`，正确应为 `totalLength - (blockNum - 1) * numPerCore`
- **corrections**（修订指令，readlist 三字段）：

```json
{
  "id": "tiling-001-1",
  "knowledge_path": "… > 函数 compute_tiling > 算法步骤 > 第4步输出字段",
  "criterion": "执行 test_tiling.cpp，8 个用例全部通过；尤其 tiling-small 期望 1/1024/100，tiling-big 期望 4/250880/247360",
  "detail": "…numPerCore = ceil(perCoreAvg / TILE_LENGTH) * TILE_LENGTH…；tailNumLastCore = totalLength - (blockNum - 1) * numPerCore…；删除原文档中两个缺陷公式"
}
```

## 3. 修订：飞轮根据产物修改知识

编排层把归因里的修订指令推入 CorrectionQueue（id=tiling-001-1），知识生成 Agent 执行修订：

- 知识 v1 → **v2**（parent_version=1）
- 修订以**追加"修订补丁"段落**形式落盘（保留 v1 原文与版本链，可回滚）：
  - 判据：8 用例全部通过（含 tiling-small 1/1024/100、tiling-big 4/250880/247360）
  - 详情：numPerCore 向上对齐 TILE_LENGTH；tailNumLastCore = totalLength - (blockNum-1) * numPerCore
- 写保护校验：src / evalset / knowledge 前后 SHA-256 快照一致（protection/before.json ↔ after.json）
- 知识泄漏检查：v2 无源码原文（断言通过）

## 4. 第 2 轮：修订后知识 → 代码 → 全通过

### 4.1 产物 D：Coder 临时代码（round_002_g001.cpp，29 行）

Coder 采纳修订补丁，公式修正并补了防御：

```cpp
uint32_t perCoreAvg = (totalLength + blockNum - 1) / blockNum;
uint32_t numPerCore = ((perCoreAvg + TILE_LENGTH - 1) / TILE_LENGTH) * TILE_LENGTH;
uint32_t tailNumLastCore = totalLength - (blockNum - 1) * numPerCore;
// 另：totalTiles == 0 时提前返回，避免除零
```

### 4.2 产物 E：评测报告（train_round_002.json）

- 编译：通过
- **测试：8/8 全通过**，confidence 1.00
- 重复评测：5 次 × 8/8，mean 1.00，variance 0.00，unstable false
- 相似度：0.21（LLM 独立实现，非抄源码）
- 失败：0
- **决策：pass**（无 reason_code）

### 4.3 产物 F：发布

- 知识 v2 状态 draft → **verified**，写入公共 knowledge_dir（tiling_v2.md，sha256 21d5ed…）
- 结果汇总：result.json（schema flywheel-result.v1，rounds=2，decision=pass）

## 5. 逐轮对比：飞轮怎么根据产物修改

| 轮次 | 知识版本 | Coder 产物 | 评测 | 决策 | 修改动作 |
|---|---|---|---|---|---|
| R1 | v1（缺陷公式） | 按缺陷实现（整除 numPerCore、取模 tail） | 0/8，conf 0.00，sim 0.49 | iterate | Review 归因 → 修订指令 tiling-001-1（指向"第4步输出字段"）→ 知识 v2 |
| R2 | v2（追加修订补丁） | 对齐 TILE_LENGTH + 剩余长度公式 + 除零防御 | 8/8，conf 1.00，sim 0.21 | pass | 知识 v2 发布（verified） |

修改链路：**评测报告（失败用例）→ 归因报告（weak_spots + 修订指令）→ 知识修订（版本 +1）→ 重新生成 → 重测**。每一跳都是文件产物交接，无角色直接对话。

## 6. 最后效果

1. **知识质量提升可量化**：R1 知识无法支持生成正确代码（0/8）→ R2 知识支持 8/8，且生成代码补了源码头文件中没有的除零防御。
2. **归因精度高**：Review 一次定位两个公式错误，修订指令三字段齐全（ID + 段落路径 + 可执行判据），修订后一轮即收敛，无需多轮试探。
3. **非抄源码**：R2 相似度 0.21，远低于抄源码基线（~0.73），说明 LLM 基于知识独立实现。
4. **可审计**：每轮知识 vN、代码 rN、评测 round_N.json、归因 round_N.json、修订指令、保护快照全部落盘（见 §7）。

## 7. 对照场景（单轮直接通过）

| 场景 | 知识起点 | 结果 | 说明 |
|---|---|---|---|
| run_llm_full | 全量正确知识（141 行 OKF） | R1 一轮 8/8，sim 0.25 | 知识质量足够时飞轮一轮收敛，不发修订 |
| run_llm_stale | 陈旧知识（仅缺 tail 计算说明） | R1 一轮 8/8，sim 0.35 | Coder 可自行补全过时点；缺陷严重到代码层才触发迭代 |

迭代只在知识缺陷**传导到代码并导致测试失败**时发生——这正是"评测对象 = 基于知识生成的代码"的设计意图。
