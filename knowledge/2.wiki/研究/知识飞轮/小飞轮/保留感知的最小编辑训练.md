# 保留感知的最小编辑训练

从对齐中导出 token 级保留信号，无需推理时搜索。

论文：PAFT: Preservation Aware Fine-Tuning for Minimal-Edit Program Repair
标识：`2604.03113`
链接：[https://arxiv.org/abs/2604.03113](https://arxiv.org/abs/2604.03113)

## 要解决的问题

论文的诊断与本项目的困境完全对应：

> 大模型对自动程序修复有效，但**通过全部测试套件的「看似合理」补丁常常重写超出必要范围的代码**，增加了评审与维护成本。

论文进一步给出根因：

> **过度编辑很常见，因为大多数 bug 是局部的，而标准监督微调没有提供关于「哪些 token 应当保留、哪些应当修改」的显式信号。**

**这一句点出了问题的本质**：问题出在**训练信号里没有「保留」这一项**，而非模型「不想」最小化。

## 方法核心

### 三项技术组合

**一、token 级保留信号**

论文从 **buggy 与 fixed 代码的对齐**中导出 token 级保留信号。做法是：对齐两个版本，**标注出哪些 token 保持不变**。

**二、全序列掩码**

把保留信号与**全序列掩码**结合。

**三、编辑难度课程**

应用**编辑难度课程（edit-difficulty curriculum）**：按难度组织训练样本。

### 关键特点：无需推理时开销

论文明确强调其收益的取得方式：

> 得出**更小、更局部化、看似合理的补丁**，且**无需推理时的搜索、重排序或后处理**。

**这一点对本项目最重要**：它意味着「提高最小性」不必增加推理成本。

## 关键数据

| 对比 | 结果 |
|---|---|
| vs 标准监督微调（StdFT） | pass@1 **提升最多 65.6%** |
| 编辑距离 | 平均编辑距离（AED）**降低最多 32.6%** |
| vs AdaPatcher（偏好学习基线） | pass@1 从 **5.9% 提升到 10.1%** |
| 编辑距离（同上场景） | 中位 AED 从 **61.0 降到 42.0** |

评测集：**Defects4J 与 HumanEval-Java**；模型：**DeepSeek-Coder-6.7B**。

### 三条解读

**第一，准确率与最小性可以同时提升。**

论文的结论是 pass@1 提升**同时**编辑距离下降。这与 `2609.04061` 的发现一致（保留指令同时降低编辑量并提升 Pass@1）。

**两篇论文独立验证了同一个反直觉结论**：约束「不许乱改」不会牺牲正确性，反而提升它。

**第二，中位编辑距离 61.0 → 42.0 是一个可感的变化。**

在这个场景下编辑量减少了约三分之一。

**第三，论文明确说收益来自「无需推理时开销」。**

这与 AURORA 那类需要额外推理的方法形成对比。对本项目的含义：**这是符合「低成本、一次调用」约束的路线**。

## 对本项目的启发

### 方案要点

**一、「保留信号」这个概念可以直接搬到提示词设计。**

论文的做法是**从对齐中导出哪些该保留**。虽然本项目不做微调，但概念可以借用：

**在提示词里显式给出「哪些内容不该动」**，而不只是「哪些该动」。

项目的 `DocGenAgent.md` 第 69 行已经包含「保留范围外正文」。可以强化的是：

| 现有 | 可补充 |
|---|---|
| 保留**范围外**正文 | 保留范围内**仍然有效**的表述 |

**理由**：`2608.21964` 的任务描述把「更新过时内容」与「保留仍有效的指导」并列为两个要求。范围约束只管住了前者的一半。

**二、「对齐导出保留信号」的思路可以用在对齐工具上。**

论文从 buggy/fixed 对齐导出信号。本项目的对应操作是**旧卡片与新卡片的对齐**：而这个对齐**可以程序化完成**（文本 diff），不需要模型。

**所以「保留信号」在小飞轮里可以是确定性的**：程序算出新旧卡片的差异，标出未变部分，把「未变部分」作为保留清单喂给模型。

**这是本分析提出的建议，论文未验证在文档场景的效果。**

**三、「无需推理时搜索或后处理」印证了低成本路线的可行性。**

论文证明在不增加推理开销的前提下可以显著改善编辑质量。这支持小飞轮「一次调用 + 确定性前置处理」的架构。

**四、编辑难度课程这个设计与本项目关系不大。**

课程学习需要训练过程，本项目不做微调。此处仅记录它的存在。

**五、训练侧的方案对本项目的参考价值是间接的。**

本项目不做微调（约束是低成本、一次调用）。所以本文的**方法不可直接用**，价值在于：

- **它证明了「保留信号」是有效信号**（两篇独立验证）
- **它给出了「最小性可以改善且不牺牲正确性」的实证**
- 它的诊断（「标准微调没有提供保留信号」）解释了为什么模型默认会过度编辑

### 与「过度编辑与最小性度量」的分工

| 文档 | 视角 | 对本项目的可用性 |
|---|---|---|
| [过度编辑与最小性度量](过度编辑与最小性度量.md) | **评测与提示词** | **可直接用**（保留指令零成本） |
| 本篇 | **训练侧** | **不可直接用**，提供机制解释 |

**结论：本项目应当采用前一文档的路线（提示词级保留指令 + 编辑距离度量），本文作为「为什么需要保留信号」的理论依据。**

## 局限

**论文实测部分**（可信）：

- Defects4J 与 HumanEval-Java 上的 pass@1 与 AED 改善
- 与 StdFT 和 AdaPatcher 的对比
- 收益无需推理时搜索、重排序或后处理

**论文提出但未量化效果的部分**：

- 三项技术各自的**单独贡献**（摘要报告的是组合结果）
- 编辑难度课程的具体设计

**本分析提出的建议**（未经验证）：

- 用程序算出的新旧卡片差异作为「保留清单」
- 提示词补充「保留范围内仍有效的表述」
- **卡片场景的效果未知**

**其他限制**：

- **需要微调，与本项目约束不符**。本项目不做训练，所以方法不可直接采用
- **场景是程序修复（Java），不是文档更新**。Java 代码有明确语法结构，对齐比自然语言文档更可靠
- **只评测 Java**，跨语言泛化性未知
- **模型是 DeepSeek-Coder-6.7B**，小模型上的结论能否推广到大模型未验证
- **pass@1 的绝对值偏低**（5.9% → 10.1% 是 AdaPatcher 场景），说明这个任务本身很难
- **「最多 65.6%」是相对提升**，绝对水平需结合基线判断
- 未讨论**训练成本**（数据量、算力）
