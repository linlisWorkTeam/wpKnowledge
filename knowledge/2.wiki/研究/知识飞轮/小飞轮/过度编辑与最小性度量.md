# 过度编辑与最小性度量

模型在改对的同时改得过多，以及如何量化「改多了多少」。

论文：When Models Edit Too Much: On the Fidelity of Minimal Code Edits
标识：`2609.04061`
链接：[https://arxiv.org/abs/2609.04061](https://arxiv.org/abs/2609.04061)

## 要解决的问题

论文开篇确立了一个前提：**大模型越来越多用于编辑已有代码，但正确性本身不够**：有用的修复还应当**最小、可评审、忠于原实现**。

论文研究的对象叫 **over-editing（过度编辑）**：模型倾向于**重写超出修复所需范围的代码**。

**这正是小飞轮 Q4「修改最小性」对应的问题**，而且这篇论文把它从「感觉」变成了「可测量」。

## 方法核心

### 构造「已知最小补丁」的评测框架

论文的核心设计在于如何让「最小性」有基准可对照：

> 我们从 400 个 BigCodeBench 问题构造评测框架，**向参考解注入受控的 AST 级损坏**，使每个修复任务都有**已知的最小补丁**。

这个设计的关键在于**先有正确答案的最小形态，再让模型去改**，从而「多改了多少」可以精确计算。评测指标是 **excess Levenshtein distance**（超出最小补丁的编辑距离）。

**对本项目的直接含义**：真实 Git Diff 没有「已知最小补丁」。所以本项目不能直接套用这个指标，需要一个近似方案（见下面的方案要点）。

### 保留指令

论文测试了一个零成本的干预：**在提示词里加入保留（preservation）指令**。

### 后训练能否学会最小编辑

论文进一步研究了两个方向：

- **监督微调（SFT）**：**过拟合到见过的损坏模式**
- **强化学习（RL）**：在**域外编辑保真度与性能保持**之间给出最好的取舍

这个对比结论说明：**最小性是一种可以「学」的性质，但监督微调学不好它**。

## 关键数据

| 项目 | 数值 |
|---|---|
| 评测框架规模 | **400 个 BigCodeBench 问题**，注入 AST 级受控损坏 |
| 过度编辑的普遍性 | **普遍存在，即使 GPT-5.5 这类强模型** |
| 关键观察 | **高 Pass@1 可以与不必要的大改动、增加的认知复杂度并存** |
| 保留指令效果之一 | excess Levenshtein distance **0.195 → 0.131** |
| 保留指令效果之二 | 增加的认知复杂度**降低 26.6%** |
| 保留指令效果之三 | **Pass@1 提升 2.3 点** |
| 两个「不」 | 收益**不**简单来自更大的推理预算，也**不**来自更大的模型 |
| 后训练对比 | SFT **过拟合**见过模式；**RL 在域外保真度与性能保持之间取舍最好** |

### 三条解读

**第一，「高准确率 + 大改动」可以并存，这是最重要的发现。**

它意味着**用正确性指标无法发现过度编辑**。小飞轮如果只检查「新卡片是否正确」，就完全看不到「改得过多」这个问题。

**第二，保留指令同时降低编辑量并提升正确性。**

这是本轮最实用的单条结论：**0.195 → 0.131 的编辑量下降，伴随 2.3 点的 Pass@1 提升**。也就是说「提醒模型哪些不该动」不仅不牺牲质量，还有正向收益。

这与常见直觉相反（通常认为约束会限制性能），所以值得强调。

**第三，收益不来自「想得更久」或「模型更大」。**

论文明确排除了这两个解释。对本项目的含义：**换个更强的模型或增加推理预算解决不了最小性问题**，必须在输入形态与指令上做。

## 对本项目的启发

### 方案要点

**一、把「编辑保真度」作为独立的质量轴。**

论文的定位很明确：**编辑保真度是代码修复质量的一个独立维度**，且**它可以被测量、也可以被学习**。

对本项目的含义：小飞轮的判定不该只有「对/错」，还应当有**「改动范围是否恰当」**。这是与事实正确性正交的一维。

**二、保留指令是零成本必加项。**

论文的实测：**excess edit distance 降 33%，认知复杂度降 26.6%，Pass@1 升 2.3 点**。

项目 `DocGenAgent.md` 第 69 行的 prompt **已经包含「保留范围外正文」**，这与论文的保留指令方向一致。论文的价值在于**给出了这个做法的量化收益**，可以据此判断是否要进一步强化。

**三、量化最小性需要一个近似方案。**

真实 diff 缺「已知最小补丁」，所以本项目无法直接算 excess edit distance。可行的近似是**两段式**：

1. 用项目既有的定位规则（第 63 行）确定「本次只允许改动哪些章节」
2. 测改动后章节与改动前的**编辑距离**，与「这条改动应有的文本变化量」比较

第 2 步的「应有变化量」没有标准答案，只能做**相对比较**（例如对比同一批卡片中改动量的分布，找离群值）。**这是本分析提出的近似方案，不是论文的方法，效果未经验证。**

**四、不要用模型判断「改动是否必要」。**

论文证明模型在正确性达标时仍会大幅过度编辑。所以「这条改动要不要做」这类判断应当由**规则**决定（详见 README 第一节的强制触发规则），模型不参与。

**五、如果要做后训练，选强化学习而非监督微调。**

论文的结论是 SFT 过拟合见过的损坏模式。不过对本项目而言后训练成本过高，这里仅作方向记录。

**六、AST 级受控损坏这个构造方法可以借用。**

如果要为小飞轮建评测集，**从正确卡片出发注入受控错误**（而不是等真实错误出现）是低成本做法。这与 `2511.19875`（见「文档一致性」专题）用规则引导变异构造不一致样本是同一思路。

### 与小飞轮 Q4 的对应

| 你列的指标 | 本文的贡献 |
|---|---|
| 修改最小性 | **给出量化定义（excess edit distance）与一个零成本干预** |
| 修改必要性 | 论文间接支持「必要性应由规则判定」 |
| 事实正确性 | 论文说明**正确性指标无法发现过度编辑**，需要独立维度 |
| 内容一致性 | 论文的「忠于原实现」对应「保留不变的上下文」 |

## 局限

**论文实测部分**（可信）：

- 400 个 BigCodeBench 问题，AST 级受控损坏，已知最小补丁
- 保留指令的三项收益（编辑距离、认知复杂度、Pass@1）
- 过度编辑在强模型上普遍存在
- SFT 与 RL 的对比结论

**论文提出但未量化效果的部分**：

- 「编辑保真度是可学习的性质」这个定位
- RL 的具体训练配置与成本

**本分析提出的建议**（未经验证）：

- 两段式近似方案（用定位规则加编辑距离测最小性）
- 用 AST 级损坏构造本项目的评测集
- **这些方案在真实知识卡片场景下的效果未知**，论文也未涉及文档场景

**其他限制**：

- **场景是代码修复，不是文档更新**。论文编辑的是代码，本项目编辑的是自然语言卡片。自然语言没有语法树，AST 级损坏与 Levenshtein distance 的适用性需要改造
- **「已知最小补丁」在真实场景不存在**，这是本文方法无法直接移植的根本原因
- 论文未报告**绝对 Pass@1 数值**，只给了变化量（+2.3 点）
- 认知复杂度（cognitive complexity）的**具体计算方式**需查原文
- **400 个问题的语言与领域**未在摘要中说明，跨语言泛化性未知
