# 父代选择：多分支版本图中从哪个历史节点继续演化

版本历史形成多个有效分支后，下一轮迭代应该从哪个节点继续？本次调研专门回答这个问题，不重复介绍 DGM、EvoGit、HGM、GEPA、ChronoMem 已收录的机制。

## 先把问题拆成两步

提问里把两件事分开了，这个区分是整个调研的起点：

- **候选集问题**：哪些版本仍然值得作为未来演化的起点
- **父代选择问题**：候选有多个时，这一轮具体从谁开始

已收录的工作只解决了第一步。EvoGit 用偏序加极大元算出「谁有资格继续」，得到的是一个集合，没有从中挑一个的规则。HGM 的 clade 聚合需要多代后代的数据才能估计，本项目跑不起。所以缺口在第二步。

第二步还需要一个额外输入：本轮的修订目标。因为「从 v4 还是 v5 继续」这个问题在没有目标时没有答案。两版各有优势、互不支配，脱离当前要修什么，选哪个都说不通。

## 深挖：Monte Carlo Elites 的 UCB 父代选择

这是找到的最接近答案的方法。它的场景原本是机器人行为库，但机制恰好对上三个约束。

### 论文原算法

MAP-Elites 在一个行为描述符网格里每格保留一个最优个体，形成「存档」。原始版本从存档里**均匀随机**抽父代，这是个明显的弱点：新发现的区域和探索了很多次的区域被同等对待。

论文把父代选择改写为多臂老虎机问题，每个个体（或每个网格）当一条臂：

```text
对存档里每个 elite i：
    n_i  = 个体 i 被选为父代的次数
    s_i  = 个体 i 的后代存活次数
          （存活 = 替换了已有 elite，或占据了空格）
    N    = 全存档的总选择次数

    score(i) = s_i / n_i  +  c * sqrt( ln(N) / n_i )

               └── 利用项 ──┘   └──── 探索项 ────┘

    n_i == 0 时 score(i) = 无穷   ← 未访问过的优先，保证每格至少被选一次

选 score 最高的个体；并列时随机取一个
```

论文设 `c = 1/√2`，因为奖励值域在 0 到 1 之间。两个关键设计：

1. **奖励用后代存活率，不用适应度**。存活意味着「产出比现状更好或占据了新区域」，这是**相对存档**的判据，不需要跨个体可比的绝对分数。
2. **个体级与网格级两种粒度**。个体级按这个人被选的次数算；网格级把同一格内所有占用过该格的选择合起来算。网格级的含义是「这片搜索区域本身有价值」，个体级的含义是「这个人有产出潜力」。

### 实测结论

在 6 维 Rastrigin、12 自由度机械臂、迷宫生成三个测试平台上：

- 论文提出的**所有**选择方法都优于原始 MAP-Elites 的均匀随机
- 网格级选择在覆盖率上普遍更好，因为它给新填充的格绝对优先权，形成「选新格 → 产出新格」的正反馈
- 个体级选择在**欺骗性地形**（Rastrigin 多峰）上更好，它能回到之前探索过的区域，带来突破
- 贪心的纯适应度选择早期最强，但**收敛到局部最优后，在 10⁵ 到 10⁶ 次评测之后被所有其他方法反超**
- 综合探索与利用的 UCB 得分取得最好的平衡与最高 QD 分数

个体级与网格级哪个更好**取决于问题地形**，这是论文自己承认的未解点。

### 可以迁移到本项目的版本

```text
# 输入：版本图、每版的评测事实、本轮修订目标
# 输出：这一轮从哪个版本开始改

candidates = 满足准入的版本          # 极大元 + 状态为 VERIFIED + 未被替代
                                     # 复用 KnowledgeLineage 的 PARENT_OF 边即可算出

if 这是第一次修订该分支:
    对每个 candidate：
        n = 该版本被选为父代的次数
        s = 该版本产生的后续版本中通过门禁的次数
        score = s/n + c*sqrt(ln(N)/n)
    选 score 最高的

else:                                # 有明确修订目标时走另一条路
    按 UCB 得分只用来决定「多个等目标版本之间选谁」
    # 目标匹配本身见下面的设计空间 Option B
```

**关键改造**：论文的「后代存活」在本项目里对应「该版本的后继版本通过了门禁」。这个信号项目已经会记录（`gateDecisionId` 和状态的 VERIFIED 迁移）。所以 UCB 的利用项不需要新数据，只需要把已有的门禁历史按谱系聚合。

**为什么它绕开了标量分数**：UCB 的奖励是**存活率**，一个 0 到 1 的相对比例，不是跨版本可比的绝对质量分。论文从没要求「v4 得 82 分、v5 得 81 分」。

**为什么它绕开了大量基准**：`n_i == 0` 时给无穷大，机制上强制每个候选至少被选一次。样本少不会让算法失效，只会让它更偏探索，这在版本数量有限时是想要的行为（宁可都试一遍）。

**为什么它仍然没有完全解决提问里的问题**：它选的是「有产出潜力的起点」，不是「与当前修订目标匹配的起点」。当前的 correction 是「缺边界条件」，而 v5 恰好就是 completeness 那一维弱，UCB 并不知道这件事。所以它解决候选集内部的排序，目标匹配需要单独一层。两者可以叠加，见设计空间 Option D。

## 深挖：三阶段递进分辨率与显式平局

这篇直接针对「信号少、差异小的时候还能不能下判断」。

### 论文原算法

在多模态大模型检查点选择中，晚期候选分数非常接近，而评测信号本身有噪声。论文把选检查点形式化为**评测不确定性下的决策问题**，用三级递进的分辨率：

```text
# 阶段一：逐点过滤
对每个候选独立打分，算平均分
   → 用途只是筛选，不用于最终决定
   → 若候选间差距小于「有限评测样本与评判模型引入的波动」，不当作有意义的差异
   → 保留一个小的近优集合（论文实测保留 4 到 6 个）

# 阶段二：列表排序
把保留的候选在同一输入、同一评测上下文下匿名并列，让评判者排名
   → 候选顺序随机化，抵消位置效应
   → Borda 式聚合排名（rank 1 最好），得到每个候选的累计得分
   → 保留排名最高的两个进决赛

# 阶段三：成对精化
两个决赛候选逐一比较，返回三种结果：
   候选 A 胜 / 候选 B 胜 / 平局
   → 平局显式保留，不随机分给任何一方
```

**核心判据**：高平局率被解释为「这两个候选在目标评测分布上难以区分」的**证据**，不是「必须强行选一个」的理由。

排序稳定性用**重复重采样评测集**来度量：在重采样的评测集上重跑整个流程，看排序翻转率。

### 实测结论

- OCR 密集输入的质量感知筛选把**排序翻转率从 32.5% 降到 11.2%**，多次运行一致性从 0.61 提到 0.84
- 在两个独立的多模态设置里观察到**验证损失走势与下游偏好背离**
- 公开的 Qwen2.5-VL-7B 复现（11 个检查点）显示逐点分数紧密聚集、最终成对比较经常被平局主导
- 重复评测**最常选出中间检查点，而不是最后一个**

最后一条对本项目直接有用：**最新版本不天然是最好**，这与「只保存最终版本会陷入局部最优」是同一个观察。

### 可以迁移到本项目的版本

```text
# 目标：在评测信号稀疏时，避免把噪声当成质量差异

第一层  用结构化事实做硬过滤，不排序
        criticalFailures > 0            → 出局
        stability 低于阈值              → 出局
        check 或 review 阻塞            → 出局
        （这些是项目已有的门禁判据，本来就是二元的）

第二层  把剩下的候选放在同一修订目标下排名
        不用绝对分，用「更符合当前目标的排前面」
        同一目标的候选才比较，跨目标不比较

第三层  只在需要二选一时做直接比较，并且允许平局
        平局 → 两个都保留，或者按覆盖度选更欠缺的那一维
```

**为什么适合本项目**：它的所有判断都是**序数**的（谁排前），不是基数的（谁高 1.3 分）。项目只有少量结构化信号，基数比较正是最不可靠的地方。

**需要注意的**：论文的第一层仍然是「逐点打分再取平均」，本项目不该照搬这一步，应该换成硬约束过滤，因为项目有 `criticalFailures` 这类明确的二元判据，比打分更可靠。

## 深挖：当多样性成为第一目标

多目标演化里有一批工作把「覆盖不同能力」当成独立目标，而非副产品。

### 论文原算法

EvoPref 做的是 LLM 对齐，但它对「怎么在多个不可比方向之间取舍」的处理方式可以搬：

```text
archive = {}                          # Pareto 归档，初始为空

每轮：
    parents = archive 内的非支配个体     # 不被任何其他个体在所有目标上同时不差
    offspring = crossover(parents)       # LoRA 感知的交叉算子
    for child in offspring:
        objectives = evaluate(child)     # 多目标评测
        if 不与 archive 内任何个体互相支配:
            archive.add(child)
            从 archive 移除被 child 支配的个体
```

关键点在于**归档的更新规则本身就是选择规则**：任何不被支配的版本都进归档，被支配的才删除。归档里的成员是平权的，都可能在下一轮被选。

EvoPref 的实测结论是：梯度方法（DPO 类）会「偏好坍缩」到窄的行为模式，而多目标演化在多样性上是主要收益来源，对齐质量的收益次要。归档组成分析还显示归档确实覆盖了不同的行为区域。

### 可以迁移到本项目的版本

这几乎是提问里 v4 与 v5 那个例子的直接对应：

```text
v4：  correctness ✓  completeness ✓  grounding ✓  simplicity ×
v5：  correctness ✓  completeness ×  grounding ✓  simplicity ✓

两者互不支配 → 都进归档 → 都保留

新的 correction：缺边界条件，要提高 completeness，不能破坏 grounding

筛选：grounding 是硬约束（correction 明确说不能破坏）
      v4 ✓ 与 v5 ✓ 都满足约束 → 都留下
排序：completeness 是当前目标
      v4 ✓ 优于 v5 × → v4 排在前面
结论：选 v4 作为本轮父代，v5 留在归档不删除
```

如果 correction 换成「文档太啰嗦，要压缩」，目标维变成 simplicity，则答案反过来变成 v5。归档不动，只是排序依据变了。

**这里回答提问里的三个选项**：应该选 v4，但 v5 **也继续保留**。选 v4 是本轮的决定，保留 v5 是候选集的决定，两者不冲突。这正是把候选集问题与父代选择问题分开的价值。

**需要注意的**：论文的评测是「每个目标一个可分数量」，本项目当前只有 `qualityScore` 一个 0 到 100 的数字加若干二元事实。要做 Pareto 支配比较，需要先把多维事实变成可比较的维度。这一步是数据改造，不是算法改造。

## 深挖：成本与质量同时作为目标

MO-CAPO 做提示词优化，但它把「成本」单列为一个优化目标，这个立场对本项目有用。知识文档越长、携带源码片段越多、越频繁重跑，成本越高，而按当前门禁口径成本完全不在判据里。

论文的做法是把性能与成本同时放进支配关系：一个候选只有在性能和成本上都不差于另一个时才算支配它。这样归档里会同时存在「贵但更好」和「便宜但够好」两批版本。

**可以迁移的部分**：本项目的 `EvaluationReport` 已经记录了 `toolchainFingerprint`、`modelConfigSummary` 等指纹字段，也有轮次预算。把「为解决这个问题花了几轮、几次模型调用」当成一个可比较维度，就能让父代选择偏好「更容易收敛的起点」，而不只是「当前质量最高的起点」。

## 评测不确定性的两个坑

两篇 2026 年的新工作发现了与父代选择直接相关的陷阱。

**归档覆盖能证明什么**（`2608.08008`）：这篇研究用质量多样性存档去修复过程奖励模型的漏洞，结论里有一个坦白的负面发现：在这个规模上，**QD 归档作为修复数据源，并不比随机或穷举攻击集更好**。质量多样性的收益在于**可审计的归档本身**，不在于搜索或修复的优越性。

这对本项目是一个重要的预警：如果打算上 QD 归档，不要预期它会自动带来更好的选择质量。它带来的主要是**可解释性和覆盖度可证明**，选择质量的提升需要另外的机制。论文还给出了覆盖率的理论边界（分数覆盖率无法控制上确界），并承认真实实验只用了每个基准 1 到 2 条轨迹的小规模。

**回滚之后状态是否还有效**（`2608.29381`）：这篇系统研究了 Agent 的检查点与回滚机制的安全性，五个失效模式里三个与本项目直接相关：

- 内部状态覆盖不完整：恢复的状态缺一部分
- 外部状态失配：检查点内的状态与其依赖的外部资源（源码版本、测试集）不匹配
- 未记录的外部副作用：回滚只撤销了内部状态

论文指出一个关键区分：**正确回滚不等于安全恢复**。一个忠实恢复的检查点，可能恢复出一个「其状态、假设和外部效果在任何合法历史中从未共存过」的执行。

对本项目的直接含义：知识版本存档在某个源码版本下通过 VERIFIED，但源码演进之后，这个版本的状态与其依赖已经失配。回滚到它，恢复出的知识可能与当前源码不符。这与项目自己的判断一致（`Evaluation.md` 记录了「评分可比性与回退实现细节仍需落实」），论文给出了这类失效的分类学。

## 设计空间：四个可信方案

每个方案都给出需要什么数据、是否需要大量历史、优缺点、对知识卡片的适配度与实现复杂度。

### Option A：Pareto 前沿 + 轮转

```text
frontier = get_non_dominated(archive)        # 互不支配的版本集合
parent   = round_robin(frontier)             # 按顺序轮流，保证每个都被试到
```

- **需要什么数据**：每个版本在各质量维度上的可比较取值
- **是否需要大量历史**：不需要。版本数少反而好，轮转一圈成本低
- **优点**：实现最简单；天然保证覆盖；不会因为某一维暂时领先就把其他分支饿死
- **缺点**：完全忽略当前修订目标；轮转可能导致把有限轮次浪费在与当前问题无关的版本上
- **对知识卡片的适配度**：中。适合项目早期、修订目标还不明确、需要先把各分支摸底的时候
- **实现复杂度**：低。支配比较加一个轮转指针即可

### Option B：Pareto 前沿 + 当前目标匹配

```text
frontier = get_non_dominated(archive)

candidates = [v for v in frontier
              if satisfies_hard_constraints(v, current_correction)]
              # 硬约束来自 correction 里写明的「不能破坏」项

parent = argmax(v in candidates, key=lambda v: goal_match(v, current_correction))
         # goal_match 只看当前目标那一维，不做加权总分

if 平局 or 目标维无法区分:
    两个都保留，本轮选覆盖度更欠缺的那个
```

- **需要什么数据**：correction 要能说清「目标维是什么」和「不能破坏什么」。项目的 `Correction` 已有 `criterion` 与 `risk` 字段，方向对，但需要把自由文本的 criterion 收敛到可映射的维度
- **是否需要大量历史**：不需要。每轮只看当前目标与候选集的对应关系
- **优点**：直接回答「修什么就找偏什么的版本」；不做加权总分，避免把不同目标塞进一个数字；硬约束保证不破坏已有能力
- **缺点**：依赖 correction 的结构化程度；如果 criterion 是自由文本，goal_match 就退化成模型打分，又引入不确定性；目标维可能没有候选能覆盖
- **对知识卡片的适配度**：高。这是对提问里那个 v4/v5 例子最直接的答案
- **实现复杂度**：中。难点不在算法，在 correction 到质量维度的映射

### Option C：质量多样性归档 + 网格条件化选择

```text
# 行为描述符 = 版本在哪个能力维度上突出
descriptor(v) = 主导维度(v)               # 例如 completeness 主导 / grounding 主导 / simplicity 主导
                                          # 也可以是多维组合，如 (完整性档位, 简洁档位)

archive[cell] = argmax_quality(v for v in versions if descriptor(v) == cell)
                                       # 每格只留一个最优

parent = archive[cell 匹配 current_correction]
         # 目标说缺 completeness → 取 completeness 主导那一格
```

- **需要什么数据**：行为描述符的定义。这是整个方案的关键设计决策，也是最难的一步
- **是否需要大量历史**：**需要一定数量**。网格太细会导致大部分格空着，反而退化成随机挑；格数应与版本数匹配
- **优点**：明确保留「擅长不同方面」的版本，与提问里「版本 A 擅长 completeness、版本 B 擅长 grounding，全部保留」的设想完全一致；选择过程可解释（目标 → 格子 → 父代）；天然防坍缩
- **缺点**：描述符设计需要领域知识，设计不好会退化成 Option A；`2608.08008` 的负面结论提醒归档本身不保证更好的选择质量；格内质量比较仍需可比较信号；版本关系（谁是谁的后代）在网格视图里丢失
- **对知识卡片的适配度**：**最高**。知识质量的多维性正是这个方法的适用条件
- **实现复杂度**：中高。描述符设计与网格粒度需要实验调，且需要先在版本图上叠加网格视图（两套视图要能对照）

### Option D：Bandit 不确定感知父代采样

```text
# Monte Carlo Elites 的 UCB，奖励换成谱系内的门禁通过率
for v in candidates:
    n = 选择次数(v)
    s = 后继通过门禁次数(v)
    score(v) = s/n + c*sqrt(ln(N)/n)
    if n == 0: score(v) = 无穷        # 保证每个候选至少试一次

# 与目标匹配叠加：先用 Option B 的硬约束过滤，再在剩下的候选里用 UCB 采样
parent = argmax(score(v) for v in 通过目标过滤的 candidates)
```

- **需要什么数据**：每个版本的「被选次数」与「后继通过门禁次数」，两者都可由 `KnowledgeLineage` 的 PARENT_OF 边加 `gateDecisionId` 统计得到
- **是否需要大量历史**：不需要，这是它的设计优点。样本少时自动偏探索
- **优点**：不需要标量质量分，奖励用的是相对存活率；保证不饿死任何候选；自然平衡探索与利用；数据完全来自项目已有记录
- **缺点**：衡量的是「产出潜力」不是「与当前目标匹配」；在欺骗性地形上个体级更好、其他地形网格级更好，论文自己没给出选择粒度的判据；UCB 需要版本数量足够多才能体现出统计意义，只有两三个分支时优势不明显
- **对知识卡片的适配度**：高。作为 Option B 的补充层最合适
- **实现复杂度**：低到中。算法简单，但要先把门禁历史按谱系聚合

### 四个方案的组合建议

这几个方案不是互斥的，层次不同：

```text
第一层 硬约束过滤        ← 门禁已有判据（criticalFailures / stability / 阻塞）
第二层 候选集计算        ← Pareto 前沿 或 极大元（Option A/B 的 front）
第三层 目标匹配排序      ← Option B（有明确目标时）或 Option C（按能力格）
第四层 目标内二选一      ← Option D 的 UCB（多个版本同样匹配目标时）
```

硬约束在最先，因为它是二元的、最可靠。候选集在第二层，回答「谁有资格」。目标匹配在第三层，回答「这一轮修什么就找偏什么的」。UCB 在最后一层，只在目标匹配分不出高下时使用。

## 研究缺口

**没有发现完全匹配的现成算法。**

项目需要的组合是：稀疏评测（无大量基准） + 多维质量（无单一标量） + 版本 DAG（可分支） + 目标条件化的父代选择 + 面向知识文档而非代码或模型权重。

逐条对照已有工作：

- **稀疏评测**：`2605.18852` 处理得最好（显式量化不确定性、允许平局），但它选的是训练检查点，不是可继续演化的版本，且没有版本图
- **多维质量**：EvoPref、MO-CAPO 给出了 Pareto 归档做法，但它们的归档成员是模型权重或提示词，且默认每个目标都有连续的评测信号
- **版本 DAG**：EvoGit 给了偏序与极大元，但它明确不做选择
- **目标条件化**：MAP-Elites 网格是最接近「按特征选起点」的机制，但它的条件化来自行为描述符而非任务目标；目标条件化的工作（curriculum、goal-conditioned RL）都在 RL 设定下，需要大量交互
- **知识文档**：没找到把上述机制用在文本知识版本管理上的工作

### 最合理的组合来源

| 缺什么 | 从哪来 | 具体拿什么 |
|---|---|---|
| 候选集怎么算 | EvoGit（已收录） | 偏序 + 极大元，用已有 `PARENT_OF` 边 |
| 多维质量怎么比 | EvoPref / MO-CAPO | Pareto 支配 + 归档保留不删除 |
| 目标怎么条件化 | MAP-Elites / `2504.14367` | 行为描述符分格，按格取父代 |
| 稀疏信号怎么稳 | `2605.18852` | 三级递进分辨率 + 显式平局 + 硬约束过滤 |
| 多个等目标候选怎么选 | `2104.08781` | UCB 存活率采样，奖励来自谱系门禁历史 |
| 归档能证明什么 | `2608.08008` | 别指望归档自动提升选择质量，收益在可审计性 |
| 回滚后状态有效性 | `2608.29381` | 五类失效模式，特别是外部状态失配 |

组合起来的最小可行版本：**硬约束过滤 → 极大元候选集 → 按当前 correction 的目标维排序 → 多个等目标时用 UCB 挑一个 → 落选的留在归档**。这套组合的每一层都有来源，且没有任何一层需要大量基准或单一标量分数。

### 需要本项目先补的两件事

1. **质量维度要可比较**。当前只有 `qualityScore` 一个 0 到 100 的数字加若干二元事实。要跑支配比较或网格分格，至少需要把 completeness、grounding、simplicity 这类维度各自变成有意义的取值。这是数据层改造，比算法改造更关键，也更难。

2. **`Correction` 的 criterion 要收敛到可映射的维度**。当前它是自由文本，如果保持自由文本，目标匹配就只能交给模型判断，又回到不确定性里。可行的中间态是给 criterion 加一个受控的维度标签。
