# 研究 / 评测

知识质量判定、代码问答和从文档生成测试的研究材料。

## 参考价值总览

星级按**对本项目的可落地程度**评定，不按论文本身影响力。五星表示可直接指导门禁实现。

| 文档 | 星级 | 可借鉴的思路 |
|---|---|---|
| [门禁自博弈风险](门禁自博弈风险.md) | ⭐⭐⭐⭐⭐ | 先确认项目已做的隔离（readablePaths 为空、不信任模型自报），再指出还需补的三处：candidate_knowledge 评分信号、historySummary 判断边界、测试有效性攻击视角 |
| [变异测试与测试集质量](变异测试与测试集质量.md) | ⭐⭐⭐⭐⭐ | 用变异体杀灭率度量测试集强度，正好补上「参考校验不证明断言充分」这个已承认的缺口 |
| [搜索预算与候选剪枝](搜索预算与候选剪枝.md) | ⭐⭐⭐⭐⭐ | `IterationBudget` 已做轮数预算，本篇补成本预算与停滞策略的具体做法，并指出 IO-19 清理与回退的耦合 |
| [EvalPlus 差分测试增强评测集](EvalPlus差分测试增强评测集.md) | ⭐⭐⭐⭐ | 测试用例太少会产生假阳性通过，差分测试自动扩充输入，直接提升门禁强度 |
| [覆盖率引导测试生成](覆盖率引导测试生成.md) | ⭐⭐⭐⭐ | 用覆盖率告知 TestGen 哪些分支未覆盖，把补漏变成程序化驱动而非模型猜 |
| [CodeJudgeBench LLM 裁判可靠性](CodeJudgeBench-LLM裁判可靠性.md) | ⭐⭐⭐⭐ | LLM 裁判存在顺序与位置偏差，与门禁自博弈风险篇配合看 |
| [防污染与效率评测](防污染与效率评测.md) | ⭐⭐⭐⭐ | 用发布时间过滤污染，评审指标不再只看对错还看效率 |
| [执行式评测与表面形式评测](执行式评测与表面形式评测.md) | ⭐⭐⭐⭐ | 执行式评测优于表面形式，是门禁选执行式的依据 |
| [Pass@k 无偏评测指标](Pass@k无偏评测指标.md) | ⭐⭐⭐ | 无偏估计避免小样本方差，多候选场景的统计口径参考 |
| [从程序文档生成自动化测试](从程序文档生成自动化测试.md) | ⭐⭐⭐ | 从注释文档生成测试，与 TestGen 的输入组织直接相关 |
| [Code2Doc 代码文档质量数据集](Code2Doc代码文档质量数据集.md) | ⭐⭐⭐ | 质量优先而非数量优先的文档数据集，可用于校准文档质量判定 |
| [CodeBLEU 代码感知评测指标](CodeBLEU代码感知评测指标.md) | ⭐⭐ | 表面形式评测的升级方向，作为辅助指标参考 |
| [语义等价评测与鲁棒性](语义等价评测与鲁棒性.md) | ⭐⭐ | 语义保持变换测鲁棒性，可用于评测集稳定性检查 |
| [代码问答基准与文档记忆区分](代码问答基准与文档记忆区分.md) | ⭐⭐ | 区分真正理解与记忆，防止评测被训练数据污染 |

## 怎么用这批材料

- **要设计门禁**：门禁自博弈风险、变异测试、执行式评测三篇是基础
- **要提升测试集强度**：EvalPlus、覆盖率引导、变异测试三篇给出具体手段
- **要防评测失效**：CodeJudgeBench、防污染、语义等价三篇覆盖判官偏差与污染
- **要控预算**：搜索预算篇与 `IterationBudget` 的实现对照看

门禁设计详见 [`../../设计/门禁与评测机制.md`](../../设计/门禁与评测机制.md)。
评测选型结论见 [`../../设计/评测的选型调研报告.md`](../../设计/评测的选型调研报告.md)。
