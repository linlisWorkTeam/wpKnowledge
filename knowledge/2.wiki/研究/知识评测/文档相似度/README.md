# 文档相似度：一致性分析怎么做得更好

文档生成流水线里的「一致性分析」环节调研。对应项目 `checkAgent` 与 `evaluation` 阶段，也是 `CheckAgent.md` 里「不能把简单名称搜索等同于行为一致性判定」这条约束的直接延伸。

## 先看结论

### 三个子问题的答案强度

| 子问题 | 有没有现成答案 | 最可直接用的材料 | 缺口 |
|---|---|---|---|
| 一 一致性怎么量化 | **部分** | METAMON（precision/recall 口径）、CCISolver（检测 F1 口径） | 覆盖率与过度声称率的独立指标没有现成定义 |
| 二 结论靠不靠谱 | **有，且有警示** | METAMON 的 0.72/0.48、CCISolver 的数据集返工、`2608.00884` 的捷径信号 | 自动评测一致性结论本身没有专用基准 |
| 三 有没有更好的组合 | **有，方向明确** | `2512.19883` 结构化改动序列、METAMON 测试捕获行为、CodeGraph 级联 | 三者的组合效果无人实测 |

### 三句话结论

**第一句：把「文档 vs 代码」换成「文档 vs 可执行行为」，是最高杠杆的一步。** METAMON 的做法是用搜索式测试生成把程序当前行为固化成测试用例，再让模型判断哪些断言与文档规格不符。这绕开了「文档不能像代码那样执行验证」这个根本困难，也让判定有可复现的依据。

**第二句：喂给模型的 diff 应该是结构化的修改活动序列，不是原始 diff 文本。** `2512.19883` 的实测是，把改动分解成「替换、删除、新增」的有序序列后，F1 比最先进方法高最多 13.54%。原始 diff 文本丢掉了改动的结构信息。

**第三句：准确率高不等于判断有依据，必须单独测「依据」这一层。** `2608.00884` 发现，删掉 Javadoc 的异常声明后，模型的异常断言预测准确率最大只掉不到一个百分点。这说明它没在读文档，而是在抓捷径信号。**一致性分析如果只报准确率，可能报告的是一堆凑巧对上的结论。**

## 一致性分析在流水线里的位置

```
Git Diff ──┐
           ├─→ 一致性分析 ──→ 四类结论 ──→ 人工评审 ──→ 发布
知识卡片 ──┘        │
                    ├─ 结构化改动点清单（确定性，程序提取）
                    ├─ 候选段落检索（embedding）
                    └─ 语义判定（模型，只在失配时介入）
```

三层信号的意义在于：**确定性层给出可核对的改动清单，检索层缩小比对范围，模型层只做最后一公里的语义判断**。项目 `CheckAgent.md` 已经写定「程序可以推导的内容不要求模型重复手填」，这三层正是这句话的具体落法。

## 量化指标：现有可用的口径

| 指标 | 口径来源 | 现有数值 | 说明 |
|---|---|---|---|
| 一致性检测 F1 | CCISolver（`2506.20558`） | **89.54%** | 目前最高，但这是方法级代码-注释 |
| 一致性检测 precision | METAMON（`2502.02794`） | **0.72** | 文档-行为不一致 |
| 一致性检测 recall | METAMON（`2502.02794`） | **0.48** | **漏报超过一半，这是关键数字** |
| 结构化 diff 提升 | `2512.19883` | **+13.54% F1** | 相对最先进方法 |
| 修复成功率 | CCISolver | **0.6533**（人工评测） | 检测之外还做修复 |

**读法**：recall 0.48 意味着纯模型方案会漏掉一半以上的不一致。**这直接说明为什么需要确定性层**：确定性层的作用是让可能被漏掉的改动有另一条路径被发现，无法靠模型自己补上。

## 需要注意的项目既有约束

`CheckAgent.md` 里有三条规则与本专题直接相关，方案设计时需要对齐：

- 「**不把编号索引、相似度算法或新的代码检测系统作为实现前提**」。本专题推荐的结构化改动序列与确定性层，属于「程序提取」而非「新的检测系统」，边界上需要说清
- 「**不能把简单名称搜索等同于行为一致性判定**」。这条正好支持 METAMON 的路线：行为要靠执行捕获，名称匹配只是候选定位
- 「**不能仅凭「未检索到名称」证明实现缺失**」。这条直接约束 UNDERSERVED 的判定方式，不能只靠「文档里搜不到这个名字」就报漏覆盖

## 检索与核实说明

**检索规模**：papers.cool 通道 48 组关键词 + 针对性 14 组核心查询，去重后 882 条编号，其中 2025 年及以后 372 条，与全仓已有 333 个标识去重后净新 335 条，精筛出相关 67 条，深入阅读 30 篇，写成单篇 7 篇。

**arXiv API 限制**：本轮 arXiv API 在本出口被硬限流（429 连续退避 250 秒未恢复），且发现其查询语法有三处陷阱：带引号短语返回 0 条、`all:A AND all:B` 返回 0 条、`all:A+B` 返回全库量级。改用 `abs:A+AND+abs:B` 语法后可用，但限流仍在。**本轮以 papers.cool 为检索主力。**

**已剔除的噪声**：关键词含 `consistency`、`comment`、`ground truth` 等泛词，命中大量无关材料，包括黎曼一致性模型、TikTok 评论分析、教育 AI 标注一致性、图像分类的 ground truth 不确定性、硬约束几何一致性等。**这些只是词面重合**，已在筛选阶段剔除 125 条。
