# 知识索引

检索与索引这一段的调研材料。对应 SearchAgent（`KF-SYS-043` / `AC-SEARCH-001`）与 IO-22 的文档描述、渐进加载索引。

SearchAgent 的目标形态是三级索引：仓库索引、卡片 YAML 头、卡片正文，支持条件索引、语义召回与渐进式加载。当前实现状态为 Planned，现有 `KnowledgeSearchApp` 提供普通查询。

星级按**对本项目的可落地程度**评定，不按论文本身影响力。

## 检索边界（务必先读）

SearchAgent 的检索范围有硬约束，调研结论不能越过这些边界：

- 只读当前状态为 `VERIFIED`、有成功发布回执、正文完整性有效的知识版本
- `ACCEPTED`、`CANDIDATE`、`LOW_CONFIDENCE`、`SUPERSEDED` 均不得进入候选集
- 过滤必须由受信读取服务在提供材料前执行，不能靠提示词或输出时过滤
- 索引或缓存只能加速检索，不能成为发布状态的第二事实源
- 不新建 `FlywheelRun`，不经 Orchestrator 或 LangGraph

## 缺口与待补

- 三级索引的具体结构尚未设计（仓库索引、YAML 头、正文的字段与关系）
- 语义召回的实现方式未选型（向量检索或图查询）
- 条件索引的过滤维度未定（模块、分类、状态之外的维度）
- 检索结果的相关性分数与质量评分需要区分，前者只表达匹配程度

## 怎么用这批材料

- **要设计卡片格式**：OKF 篇与 Cannbot 篇给出头部字段与正文分离的既有做法
- **要设计索引层级**：先明确一级仓库索引与二级卡片头的字段划分，再考虑语义召回
- **要防越权**：检索边界一节列出的约束来自项目设计，任何索引方案都不能放宽
