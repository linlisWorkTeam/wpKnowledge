# 研究 · 知识飞轮调研材料

调研材料按五类业务阶段组织，与项目的五个业务阶段一一对应（依据 `domain-knowledge` 的 IO-01：知识生成、检索、飞轮、评测、关联）。每篇材料记录来源、置信度、核心方法、局限和对本项目的启发。

星级按**对本项目的可落地程度**评定，不按论文本身影响力。五星表示可直接指导实现决策。各目录 README 里有完整的逐篇星级与可借鉴思路。

## 五个目录

| 目录 | 对应项目环节 | 收什么 | 篇数 |
|---|---|---|---|
| [`知识生成/`](知识生成/) | `doc_gen` 阶段、`candidate_knowledge` | 源码到知识文档、文档结构与一致性 | 9 |
| [`知识索引/`](知识索引/) | SearchAgent、IO-22 渐进加载索引 | 检索、卡片格式、三级索引 | 3 |
| [`知识飞轮/`](知识飞轮/) | `workflow` 模块、停止与回退 | 轮次循环、状态推进、归档、预算 | 14 |
| [`知识评测/`](知识评测/) | `evaluation` 阶段、`testGenAgent` | 测试生成、质量指标、门禁可信度 | 14 |
| [`知识关联/`](知识关联/) | `association` 模块（IO-23 延期） | 外部知识关联 | 1 |
| [`版本管理/`](版本管理/) | 跨环节（`KnowledgeVersion` 与回退） | 知识卡片的版本组织、选择与回滚 | 12 |
| [`增量维护/`](增量维护/) | 跨环节（`Source` 漂移、`doc_gen` 修订入口） | 代码变更驱动的增量更新、漂移与膨胀风险 | 7 |

**飞轮与评测的切分**：评测产出事实，飞轮决定下一步。判断知识对不对的放评测，轮次怎么走、何时停、要不要回退的放飞轮。

**版本管理的定位**：它不绑定单一阶段，解决的是「只保存最终版本会陷入局部最优」。版本关系、回滚定位、选择依据、机制保障四类路线都在这个目录，与知识飞轮目录的区别是飞轮关注**单次循环怎么走**，版本管理关注**多个版本之间怎么组织**。

**增量维护的定位**：同样不绑定单一阶段，解决的是「代码改了，不想每次全量重跑」。它与版本管理的区别是：版本管理关注**版本之间怎么组织和选择**，增量维护关注**怎么从代码变更推导出该更新什么**。这个方向有一篇重要的反面证据（知识会无限膨胀，全量重写治不好），动手前建议先读。
