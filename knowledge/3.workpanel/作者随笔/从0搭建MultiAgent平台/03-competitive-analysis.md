# 3 · 竞品对比：优点与缺点

> 总分总：先在"定位地图"上给 ohMyWorkPanel 找位置，再逐类对比优缺点，最后回到它真正的差异化主张。
> 快照日期：2026-08-23（star 数为 GitHub 快照，仅供参考）。

---

## 总：它不在跟谁打，它在补一个空位

市面上和"AI 协作"沾边的产品可以分四类：

| 类别 | 代表 | 解决的问题 | 它们不解决的 |
|------|------|-----------|------------|
| Agent 编排框架 | LangGraph / CrewAI / AutoGen / OpenAI Agents SDK | 代码里编排多 Agent 流程 | 群聊界面、本机 CLI 复用、非程序员的使用体验 |
| Agent 平台/助理 | Clowder / OpenClaw / 各类 AI 工作台 | 给 Agent 一个家（记忆/身份/渠道） | 轻量、单机、与"我已有的 CLI"无缝复用 |
| 互操作协议 | A2A / MCP | Agent 之间、Agent 与工具之间的标准协议 | 产品本身：协议不提供界面与任务管理 |
| IM 里接 AI | 企业微信/飞书机器人、群聊机器人 | 在聊天里调机器人 | 任务状态/工作区/多 Agent 编排的深度绑定 |

**ohMyWorkPanel 的位置：把「编排框架的能力」用「群聊的形式」包起来，跑在「用户自己的机器」上，reuse「用户已经装好的 CLI」。** 它的直接同类是 Clowder / OpenClaw；与框架和协议则是互补关系。

## 分：逐类对比

### 同类直接对比：ohMyWorkPanel × Clowder × OpenClaw

| 维度 | ohMyWorkPanel | Clowder（猫咖） | OpenClaw |
|------|---------------|-----------------|----------|
| 定位 | 本地优先多 Agent **群聊面板** | 本地优先多 Agent **团队平台**（身份/互审/记忆） | 个人 AI **助理**与多渠道生态 |
| 形态 | Tauri 桌面 + Web（:8080） | Electron 桌面 + Next.js Web（:3003）+ Redis | CLI / 服务/多渠道入口 |
| Agent 接入 | 复用本机已登录 CLI（Codex/Claude/Cursor/…） | 复用 CLI + **跨模型互审**（Claude 写、GPT 审） | 自带/多模型多渠道 |
| 协作单元 | 群 + @ 消息 + 任务状态机 | Threads + 猫（人格身份）+ 58 项技能 + A2A | 对话渠道 |
| 记忆/人格 | 无内置长期记忆（工作区即上下文） | **猫人格 + 共享记忆 + SOP 守护**（灵魂） | 会话记忆/渠道记忆 |
| 数据模型 | SQLite（单文件） | SQLite + Redis（会话/任务） | 本地存储 |
| 开源状态 | MIT（2026-08 开源，1⭐） | MIT（2.7k⭐/701 fork） | 高星生态项目 |
| 治理复杂度 | 低：一条命令跑起来 | 中：desktop 安装包自带运行时 | 低-中 |

**ohMyWorkPanel 的相对优点**
1. **最轻的"多 Agent 群聊"上手路径**：不需要 Redis、不需要理解 Threads/猫体系，克隆 → `cargo run` → 建群 → @Agent；
2. **界面即工作台**：任务状态、轨迹、审批都长在聊天流里，对"只想管几个 Agent 干活"的人最直观；
3. **CLI 复用更纯粹**：适配器目录显式声明能力，接入新 CLI 是新适配器，不改核心；
4. **扩展宿主即插即用**：四类贡献点 + 同源反代，接入 PanelLive 这类扩展不用改平台仓；
5. **完全本地**：连"安装"都只有 Rust 服务这一个进程，无外围服务依赖。

**ohMyWorkPanel 的相对缺点**
1. **没有记忆与人格**：Agent 之间不共享记忆、没有"团队性格"——长期协作的粘性弱于 Clowder 的猫咖体系；
2. **没有跨模型互审/团队治理**：任务 = 单 CLI 执行，没有"猫之间互审、SOP 守护"这类团队纪律层；
3. **单机边界**：群与任务状态不跨机器（跨站留给 Connecter，且 Connecter 尚在早期）；
4. **生态处于起步**：2.7k vs 1 star 的差距，社区贡献、issue 沉淀、集成案例都还很少；
5. **移动/窄屏**：Web 版本明确不是移动端优先；
6. **无托管运维**：备份、TLS、访问控制都要用户自己负责（README 明示边界）。

### 与编排框架对比

| | ohMyWorkPanel | LangGraph / CrewAI / AutoGen |
|---|---|---|
| 使用者 | 人类在群里指挥 | 开发者写代码编排 |
| 形态 | 产品（有界面/任务管理/审批） | 库/框架 |
| 关系 | **互补**——框架可作为某个 CLI 适配器的内部实现 | 不是直接竞品 |

### 与协议（A2A / MCP）对比

A2A 是"Agent 之间说话的语言"，ohMyWorkPanel 是"人和 Agent 一起工作的房间"。ohMyWorkPanel 已经内置 A2A 白名单（`prefix.*` 技能），未来应把 A2A/MCP 作为适配层协议持续扩展——**协议是生态的语法，面板是生态的客厅**。

---

## 总：可持续的差异化主张

1. **"看得见的 AI 团队"**：多 Agent 平台的信任问题 = 黑盒问题；ohMyWorkPanel 用群聊+任务轨迹+审批把执行完全摊开在阳光下;
2. **"你的 CLI，你的面板"**：不锁定模型/厂商，用户已付费的 CLI 即插即用，迁移成本趋近于零;
3. **"本地优先的开放客厅"**：别人的生态要么在云端（托管），要么在某个模型阵营里；ohMyWorkPanel 站在本地，向所有 Agent 平台开门——这正是它与 Connecter 一起能讲的故事（见 [04 演进方向](04-evolution-roadmap.md)、[clowder 对比](../../调研/clowder-ai调研/02-compare-with-ohMyWorkPanel.md)）。

> 风险提示：记忆/人格/互审是 Clowder 的长板，也是"情绪价值"叙事的钥匙；ohMyWorkPanel 若长期不补这一点，会在生态成熟期被拉开差距（详见 [06 战略思考](06-strategy-thinking.md) 的 soul 讨论）。
