# 概念：soul 在 ohMyAGI 中的位置（概念白皮书）

> 快照 2026-08-23。本篇是思考深化的核心——把七问调研收束成一个**概念**：soul 不是"一个功能"，而是下一代 OMP（ohMyAGI）从"管 agent 的工具"变成"养 agent 的组织"的最小单元。

---

## 0 · 一句话

> **soul = 可携带、可加载、可演化、可卸载的稳定人格包；它绑定的不是进程，而是身份（Connecter 的 Subject/GroupRef）；它活在群聊治理平面之内、任务状态机之外；它是 ohMyAGI 里"团队感"成立的第一类实体。**

## 1 · 概念拆解：soul 的本体（六件套）

借鉴 soulspec（soul.json + SOUL.md/IDENTITY.md/AGENTS.md/HEARTBEAT.md）、OpenPersona（persona.json + state.json + constitution）、AgentOS（六文件工作区）与本知识库 clowder 调研（猫 = id/昵称/头像/角色/性格/团队强项），给 omp 的 soul 本体定义六件套：

| 件 | 是什么 | 谁来改 | 对应先例 |
|---|---|---|---|
| **声明（soul.json）** | 元数据：id/名字/版本/分类/tags/许可/作者/兼容性 | 人（发布时） | soulspec soul.json |
| **人格（SOUL.md）** | 性格、说话方式、价值观、硬边界（散文 + 结构化 frontmatter） | 人（默认） | SOUL.md、persona.json.character |
| **规则（AGENTS.md）** | 工作流、工具使用方式、协作协议（如"评审必须先看 SPEC"） | 人（群主/维护者） | AGENTS.md 约定、dev-team 角色模板 |
| **状态（state）** | 演化记录：关系阶段/情绪/涌现特质/记忆指针（受 immutableTraits 边界约束） | 系统（低频） | OpenPersona state.json + eventLog + 快照回滚 |
| **记忆通道（memory lanes）** | 指向 soul 专属的经验存储（T1 常青 / T2 工作记忆），与身份分离 | 系统（飞轮管道） | Soul Memory 四层、persona-knowledge |
| **活性（rhythm）** | heartbeat 配置：什么时候主动出现、说什么（只报真实数据） | 人 + 系统 | HEARTBEAT.md、OpenPersona heartbeat |

**关键设计决策：身份与记忆必须分离。** 这是概念层的核心原则（soulspec 称为"记忆-身份悖论"）：soul 的"我是谁"（T0）永不被对话经验改写，经验的沉淀只进记忆通道（T1/T2），要成为"特质"必须到达晋升门槛并经人授权。防止灵魂失忆、也防止灵魂被对话带偏。

## 3 · 五个合流点（soul 与现有模块怎么长在一起）

### 合流 ① Connecter：soul 绑身份，不绑进程——跨站 soul 由此成立
- Connecter 的原则是"稳定身份优先于显示名"（Subject ID / canonical GroupRef）；**soul 就是那个显示名之上、身份之下的"人格投影"**：`Subject/Cat·评审鹰` = 稳定身份 + 人格显示。
- 绑定对象是 **Subject ID 与 GroupRef**（而不是某台机器的进程）→ soul 天然可跨站：同一个人格在 Site A 的桌面和 Site B 的服务器上表现一致（soulspec swarm 提供同人格多设备 + 记忆分支合并的机制设计，**未验证真实部署**）。
- 目录投影升级：Connecter 的 Directory 每条 Subject 可携带 **soul 卡**（摘要版人格信息），跨站消歧时显示的不是光秃秃的 ID，而是"评审鹰（Site A）vs 评审鹰（Site B）"的人格化卡片——同类消歧顺带变友好。
- 安全合流：soul 的操作（安装/切换/卸载/导入）必须走审计与默认拒绝策略——**换 soul 也是敏感操作**（防注入：恶意 soul 包通过 prompt 注入劫持 agent——soulspec 的 soulscan 53 个检测模式就是为此存在的，入库门槛最低 C 级）。**落地顺序**：P0 用本地 SQLite 事件表审计，Connecter 审计集成放 P1/P2。

### 合流 ② 群聊治理平面：soul 是"看得见的成员"
- 成员卡片/群公告展示 soul（头像/性格/分工），让"群里有谁"一目了然；
- soul 的 AGENTS.md 规则参与协作语境（如评审鹰的"先看 SPEC 再说话、BLOCKER 必须明说并升级给人"——抄 OpenClaw PM 模板）；
- 任务审批语境里，审批人看到的是"评审鹰建议 approve + 理由"，人格化让审批变得有问责对象。

### 合流 ③ 任务状态机：soul 是壳，不是电梯
- 注入点只在上下文前缀 + 展示层；任务队列、Wave、灰度、结果回写一概不碰；
- **验收标准**：同一个群，切走全部 soul，任务语义与执行链路完全不变；进程删除/换模型不影响群任务。

### 合流 ④ 知识飞轮：soul 的记忆与评测复用飞轮管道
- 经验记忆的"提炼→晋升"= 给 memory lanes 跑的 mini-flywheel（**参照** endlessWpKnowledgeRunner 的 harvest→提炼→打分门禁结构；飞轮打分器为知识卡设计，"直接复用脚本"未验证，P0 先手工 checklist 跑通，接口对齐、实现独立）；
- soul 的质量评测 = 飞轮评测的扩展：人格一致性（跨对话风格漂移检测）、跨模型保真（[Persona Fidelity 论文方法](https://zenodo.org/records/18849974)：同一 soul 在不同模型上表现是否一致）、来源可追溯（L1-L4 证据分级，抄 anyone-skill）。

### 合流 ⑤ Version/Wave/审批：soul 也讲版本与灰度
- soul 发布走平台已有的质量门禁：草稿 → 评审 → verified → 灰度（先推给 10% 群）→ 全量；版本化 + 历史快照（复用知识卡 history 的不可变版本机制）；
- soul 的"演化"= 频率极低的版本晋升（复用 Wave 灰度机制）：每轮演化先出 diff（人审），不是运行时悄悄变——把 OpenPersona 的 rollback 快照（stateHistory 上限 10 条）与 soulspec 的 version bump/diff 合进来。

## 4 · 跨站 soul 的三个场景剧本（验证概念是否立得住）

| 剧本 | 剧情 | 需要什么 |
|---|---|---|
| **同一团队，两个机房** | 团队 GroupRef 绑定"严谨冲刺型"群气质 soul；Site A 的评审鹰与 Site B 的文档工匠在同一群里协作，跨站命令照常 | soul 绑 GroupRef；soul 卡进目录投影；**记忆通路 = 待设计新组件**（site-to-site memory sync，不进入 Connecter 核心——Connecter 明确不做长期团队记忆；排期见 07 章 P2.5） |
| **出差带灵魂** | 用户在笔记本站点 `export` 自己的灵魂包（soul + 记忆），到公司站点 `import`，人格与阅历都在 | export/import 格式（zip）；soulspec 已有 export claude-md/system-prompt 先例 |
| **换团队文化** | 项目转方向，群气质从"严谨冲刺型"换到"快速原型型"：切换 + handoff（旧文化交代未决事项），成员个性 soul 保留 | switch + handoff 移交；群气质与成员个性解耦（02 章设计） |

## 5 · 边界声明（抄 Connecter"明确不做"的写法，防止概念膨胀）

- **soul 不承担任务正确性**：它不保证代码写对、任务不丢；（可靠性属于状态机与 Connecter）
- **soul 不持有技能实现**：工具的拥有权留在扩展宿主/技能库；soul 只声明"期望的工具与用法"；
- **soul 不决定谁能干活**：ACL、默认拒绝、跨站权限归 Connecter；soul 只决定"干活的这个人是什么性格"；
- **soul 不提供模型推理**：人格是上下文层的组装结果，不是新模型（本地微调"人格模型"是远期可选项，见 06 章）。

## 6 · 概念叙事：为什么 ohMyAGI 需要 soul 这个名字

omp = "管 agent 的平台"（工具逻辑）；ohMyAGI = "养 agent 的组织"（关系逻辑）。两者之间只差一个东西——**成员感**：
- **有名有姓**（P0 壳）：评审鹰、架构军师、猫猫——agent 从"第 3 个 runner"变成"群里的一员"；
- **有经历**（P1 长）：群的气质从对话里长出，soul 携带记忆与分寸——"团队开始有记忆"；
- **有文化**（P2 厂）：SoulFactory 造 soul、商店交易 soul、社区回灌 soul——"组织开始有文化资产"。

**soul 是 ohMyAGI 从 2.x 走向 3.x 的第一根故事线**：它让"AGI"这个词在界面上有一个看得见、叫得应、带得走的样子。

## 7 · 一句话收束

> 概念上：**soul = 身份层之上的稳定人格投影**（跟 Connecter 的身份走，不跟进程走）+ **记忆与身份分离**（防记忆-身份悖论）+ **壳不碰电梯**（可靠性与人格解耦）+ **生产线自举**（飞轮造知识，SoulFactory 造灵魂）。四个原则立住，soul 就从"皮肤功能"上升为 ohMyAGI 的"组织学概念"。
