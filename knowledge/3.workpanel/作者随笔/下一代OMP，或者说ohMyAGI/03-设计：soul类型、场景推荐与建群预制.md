# 设计：soul 类型、场景推荐与建群预制（问 4）

> 快照 2026-08-23。问题拆成三个：① 能支持加载哪些 soul？② 哪些对项目开发有好处、适用于什么场景？③ 能不能在创建群聊时预制/推荐 soul？

---

## 1 · 能加载哪些 soul：一份分类货架（建议 omp 的 soul store 目录）

参考现有生态的分类（soulspec 的 category 字段如 `developer-tools`/`work/devops`、OpenClaw 画廊 36+ 模板、OpenPersona 6 个预设、dev-team 角色模板），给 omp 建议五类货架：

| 货架 | 是什么 | 现成先例 | 对 omp 的价值 |
|---|---|---|---|
| **工程角色类** | 评审鹰/架构军师/文档工匠/测试鹰眼/安全卫士/PM 进度管家 | OpenClaw dev-team 的 PM/Dev/QA/Security/Lead 角色模板（[ROLE_TEMPLATES](https://github.com/LeoYeAI/openclaw-master-skills/blob/main/skills/dev-team/references/ROLE_TEMPLATES.md)）、soulspec 的 surgical-coder | **对开发收益最高**，直接服务 omp 主场景（多 Agent 写代码） |
| **场景类** | 调研/复盘/会议/发布/答疑 | 本知识库已有"调研类工作流""复盘"实践 | 与 omp 现有群聊模式一一对应 |
| **团队文化类** | MBTI 16 型（16 种团队气质）、极客/禅意/质检文化 | clowder 调研建议的"MBTI 首发皮肤" | 情绪价值挂钩，用户自带认同感。注意：**MBTI® 是注册商标，且信效度有学术争议**——用作营销语言可以，用作团队气质"科学依据"不行；付费 SKU 命名建议绕开商标词（用"军师队/创意队"自创名 + MBTI 映射） |
| **陪伴/导师类** | 斯多葛导师、猫咖猫猫、生活助理 | OpenPersona 的 samantha/stoic-mentor/life-assistant/health-butler 预设 | 留存天花板（clowder 作者主张，无公开数据，待验证），后期再做 |
| **品牌类** | 把一个品牌/创始人的人格做成 soul | OpenPersona 的 brand-persona-skill | 面向"to 团队"场景的差异化卖点 |

## 2 · 哪些对开发最有好处：工程角色类的四张王牌

按"对项目的可感知收益"排序（推断，证据来自 OpenClaw 角色模板的分工设计与 clowder"跨模型互审"的验证）：

1. **评审鹰（Code Reviewer）**——最硬核的收益：把"不可能三角"变成"另一双眼睛";clowder 证明"Claude 写、GPT 审"能提升可信度，soul 让这个角色有名字、有脾气、有稳定的评审标准。
2. **架构军师（Architect）**——soulspec 甚至专门有 `SOUL.architect.md`（Architect CEO 模板）；在动手前做设计评审，收益在"少返工"。
3. **文档工匠（Documenter）**——接 omp 生态里"文档生成"研究（DocAgent/RepoAgent 一族），文档 soul 把能力人格化。
4. **PM 进度管家（Orchestrator）**——与 omp 的任务状态机天然互补：群公告、BLOCKER 上报、验收条件（OpenClaw PM 模板的原话："把 BLOCKER 明说并升级给人类"）。

**各角色的适用场景一句话**：开发群配"评审鹰+架构军师+文档工匠+测试鹰眼"四人众；攻坚群配"独裁审稿人"（评审鹰的严格变体，不在首发 12 SKU 正册内，P2 补录）；调研群配"书虫+怀疑论者"；复盘群配"复盘导师"。

## 3 · 建群预制与默认推荐：可以做，且是 soul 功能的第一入口

**结论：能，而且强烈建议做——"创建群聊"就是 soul 的第一触点，胜过任何单独的 soul 商店页面。**

设计（贴合 omp 的"群 = 工作单元"形态）：

```
用户点"新建群聊"
  → 选择群用途：写代码 / 文档调研 / 复盘评审 / 答疑客服 / 全员自由
  → 系统给出 3 套推荐组合（推荐组合以 09 章 SKU 为唯一事实源；群气质 soul × 成员 soul），每套一句话卖点：
     例（开发群，与 09 章映射表一致）：
     【严谨冲刺型】评审鹰 + 架构军师 + 文档工匠 + 测试鹰眼 + PM 管家
     【快速原型型】评审鹰 + 文档工匠（少而快）
     【氛围型】INTJ 军师队 + 评审鹰（文化皮肤见 09 章 C 类）
  → 用户可"换掉任何一个成员 soul"，也可"不带 soul 先用默认"
```

**为什么推荐要在建群时做**：① 若 omp 建群流程会让用户先选用途，则零成本顺路（**此为假设，P0 前需核对 omp 建群表单现状**：是否必填用途、群资料有哪些字段、消息卡片能力）；② 推荐质量可以随"群用途 × 项目类型 × 语言栈"持续学习（用现有评测/usage 信号回流）；③ soulspec 的 `category` + tags 就是为搜索/推荐设计的字段，算法可以极简（标签匹配 + 打分重排，复用知识飞轮检索的成熟做法）。
**表述修正**："第一入口"为**建议定位**而非定论：P0 用漏斗数据验证"建群页 soul 接受率 vs 商店页直达率"，若商店页更高则调整入口优先级。

**注意两个边界**：
- 推荐 ≠ 强制：默认给"无 soul"的选项，保证老用户路径不变（soul 是加层，不是换产品）；
- 推荐逻辑先手动映射表起步（群用途 → 角色组合），不急着上模型；等有 usage 数据再重排。

## 4 · 一句话回答

> 能加载五类货架；对开发收益最高的是工程角色类（评审/架构/文档/测试/PM）；建群时按"群用途 → 推荐组合"做预制推荐是 soul 功能性价比最高的第一入口——它同时验证了"加载、推荐、换肤"三条链路。
