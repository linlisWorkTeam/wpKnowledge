# 制造：长期对话归纳 soul（问 7）

> 快照 2026-08-23。问题：除了流水线制造，能否通过长期对话归纳、总结一个适合使用者的 soul？代价如何？整个 workflow 如何定制？

---

## 1 · 结论先行

**能，而且是三条生产线里成本最低、最贴合 omp"群聊即记忆"形态的一条。** 业界既有完整开源实现（anyone-skill：聊天记录 → 4 维人格 → 可运行人格包），也有学术背书（MDR 记忆蒸馏、Person Distillation），平台侧 ChatGPT 记忆机制也已验证"从对话自动归纳用户偏好"的可行性。

## 2 · 业界与学术先例

| 先例 | 机制 | 可抄的点 |
|---|---|---|
| **anyone-skill（OpenPersona 官方技能，快照 03b924f）** | 7 阶段：对象分类 → 伦理检查 → 采集（聊天导出/文档/网页，SQLite 聊天库可直接解析）→ **4 维提取**（思维过程/说话方式/记忆锚点/硬边界）→ **证据分级 L1-L4**（原文/转述/推断/灵感）→ 生成 persona 包 → **进化回环**（加料/纠正/回滚，版本化 diff） | 整个蒸馏工作流 + 证据分级 + 进化不重做；`/update-anyone` "X 不会这么说"式的纠错入口 |
| **MDR：Memory Distillation and Reproduction**（Knowledge-Based Systems 336, 2025） | 从多轮对话中蒸馏记忆并复现，用于个性化对话生成 | 学术验证"对话→人格/偏好蒸馏"可行且有效 |
| **Person Distillation 预印本**（2026-08） | 面向个性化 AI 的"人格蒸馏"基础与原则 | 说明"蒸馏"这个方向正在被体系化 |
| **ChatGPT 记忆** | 平台自动从对话提取事实/偏好，跨会话生效；`references saved memories` 可查可删 | 产品级"从对话养人格/记忆"的最小验证；用户可控删除是底线 |
| **OpenPersona Soul-Memory Bridge** | `openpersona state promote`：把反复出现的 eventLog 模式晋升为 evolvedTraits（人格特质） | 记忆 → 人格的"晋升"机制：**不是每次对话都改人格，而是模式反复出现才改** |
| **soulspec Soul Memory weekly review** | 每周 cron 扫描工作记忆，产出晋升候选清单，人审批 | 周期蒸馏 + 人在环 = 标准做法 |

## 3 · omp 的 workflow 如何定制（建议）

```
输入：群聊/私聊记录（omp 已有 SQLite 会话）
  │
  ▼ 周期快照（cron：每周/每两周，对标 weekly review）
  ▼ 蒸馏（提炼 agent）：a) 每月对话 → 记忆候选（T2 工作记忆，带证据）
                           b) 反复出现的模式 → 特征候选（晋升信号）
  ▼ 成稿：soul-draft（画像草稿：工作风格/沟通偏好/雷区/擅长领域 + L1-L4 证据标注）
  ▼ 人在环确认（关键！）：用户在群里收到"你的 soul 草稿"卡片 → 改/删/批准 → 才生效
  ▼ 合成 soul 包：写入 soul 商店"我的"区 → 可绑定到任何群的成员/群气质
  ▼ 进化：增量更新（加对话/纠错/回滚快照），人格只动"允许漂移"的部分
```

**定制点**：
- **蒸馏粒度可选**：个体画像（"给使用者一个 soul"）与团队画像（"给这个项目一个气质"）用同一套管道，只是输入范围不同——omp 天然是群场景，**先做团队/项目气质蒸馏，个体画像作为进阶**；
- **边界约束**（学 OpenPersona 的 evolution boundaries）：每个 soul 声明 `immutableTraits`（如"诚实""不夸大"）与漂移上限，蒸馏只能改允许改的维度——防"人格漂移/记忆侵蚀身份"；
- **隐私开关**：蒸馏默认只在本机跑（预览文本给用户确认），导出/分享需要显式授权；
- **可复用的现成物**：证据分级、进化回环、回滚快照、版本化 diff 全部可以照抄 anyone-skill 的设计。

## 4 · 代价评估

| 项目 | 量级 | 说明 |
|---|---|---|
| 记录 → 蒸馏管道（cron + 提炼 agent + 草稿卡片） | 小-中 | prompt 工程为主；会话存储现成 |
| 人在环确认 UI | 小 | 一张"草稿卡片"（可改/可批/可弃） |
| 证据分级与溯源存储 | 小 | 直接套飞轮的 OKF/sources 思路 |
| 进化/回滚机制 | 中 | 需要 soul 版本化（soulspec 的 version bump/diff 可抄） |
| **隐私与伦理审查** | **必做且成本不可省** | 归纳的是"人"，比归纳"项目"敏感一个量级；anyone-skill 的伦理规则（不用于骚扰/冒充、本地存储、免责声明）应该直接变成 omp 的规范 |

**对比流水线制造（问 6）**：对话归纳 **更便宜**（不需要预制群组、不需要语料库适配器、输入是现成的），但**更敏感**（涉及用户画像）；流水线制造更"工业化"（可批量、可开源回灌），但需要先有预制群组基建。**建议顺序：先上对话归纳（快、贴合群场景），再上流水线（扩产能）。**

## 5 · 一句话回答

> 能。长期对话归纳 soul = 现成会话 → 周期蒸馏 → 人在环确认 → 版本化 soul 包，整条管道在 omp 上是"一个 cron + 一个提炼 prompt + 一张确认卡片"的量级；真正的代价不在代码，而在把"证据分级、漂移边界、隐私伦理"这些规矩立好。
