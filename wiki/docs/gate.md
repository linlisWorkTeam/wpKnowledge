# 门禁 / 评测机制（Gate）

> 最后更新：2026-08-20

## 1. 目的

为知识文档设置**质量门槛**：只有通过评测的知识，才被认为是合格、可信的知识。

## 2. 基本机制

- **评测方式（TDD 驱动）**：用例集 = **需求描述 + 预置单元测试（UT）**。Coder 根据"需求描述 + 知识库"生成代码，运行预置 UT，以 UT 通过率作为评测信号。
- **通过条件**：UT 通过率达到门限（默认全部通过，可配置）。
- **置信度**：通过的用例数 / 总用例数，提供给知识飞轮做迭代。
- **未通过**：进入飞轮反馈循环继续优化知识（见 [flywheel.md](flywheel.md)）。

## 3. 评测维度（已定：TDD 为主，相似度为辅）

> ✅ 2026-08-20 决定：评测主信号 = **UT 测试通过率**（TDD），相似度对比降为辅助信号。

| 信号 | 角色 | 说明 |
|------|------|------|
| **UT 测试通过率** | 🥇 主信号 | 预置单元测试运行结果，二值（通过/失败），客观无歧义，验证**行为等价** |
| **相似度对比** | 🥈 辅助信号 | 仅在 UT 覆盖盲区时启用：验证**还原度**（行为对但实现完全不同的场景） |
| 编译检查 | 前置 | 代码能编译是跑 UT 的前提 |
| LLM 打分 | 不用 | 主观不稳定，违背客观信号优先（Fragility） |

**为什么 TDD 做主信号**：执行反馈是所有反馈信号中最有效的（依据 [self-debugging.md](../research/feedback-loop/self-debugging.md)）；测试先行 = 测试即规格的可执行形式；置信度天然 = 通过用例数/总用例数。

**相似度保留的原因**：UT 只验证测到的行为，覆盖不到的代码（边界/性能/隐式契约）可能"测试全过但实现错误"；且飞轮目标是"还原源码"，相似度验证还原度。

## 3.5 门禁评测的可靠性约束 ⚠️

> 依据：*On the Fragility of Self-Improving Agents*（arXiv 2608.18066，2026-08）

门禁是飞轮的"裁判"，裁判不可靠则飞轮方向不可靠。评测必须遵守：

- **重复评测**：知识是否通过门禁，以多次重复评测（建议 ≥ 5 次）的均值 ± 方差为准，不以单次结果判定。
- **防作弊（防背源码）**：评测用代码必须是 Agent 无法靠预训练记忆"背"出来的——优先用私有代码，公开代码需做变换（改命名/结构调整）。否则高分可能来自"见过源码"而非"读懂知识"（参考 Code-QA-Bench）。
- **多信号组合**：建议门禁 = 源码对比（结构）+ 编译检查（环境）+ 测试（结果，有则用）多信号组合，单一指标会误判（功能等价但写法不同的代码会被相似度误杀）。
- **评测集独立**：用于评测的知识/代码，不得参与知识生成时的上下文——保证门禁测的是"知识本身能否还原代码"。
- **定义到可执行级别**：80% 怎么算、对齐粒度、允许差异类型，必须写成可执行规则，防止规格模糊导致飞轮跑偏。

## 3.6 评测闭环（TDD 驱动）⭐

> 来源：项目讨论共识（2026-08-20）。目标：**用测试用例驱动知识库迭代，提升知识库生成代码的质量。**

### 输入输出定义

| 要素 | 内容 |
|------|------|
| **输入** | 需求描述（用例的题目） |
| **预置 UT** | 单元测试（测试先行，即 TDD 的测试规格；从需求描述生成或由标准代码派生） |
| **实际输出** | 需求描述 + 知识库生成的临时代码 |
| **评测方式** | 对临时代码运行预置 UT，统计通过率 |

### 判断逻辑

```
UT 全部通过（默认）  →  通过  →  停止
存在未通过的 UT      →  失败  →  进入知识迭代
```

### 置信度计算与用途

- **置信度** = 通过的用例数 / 总用例数（公式明确，无需再定）
- **用途**：提供给**知识飞轮**做迭代——置信度高的知识稳定保留，置信度低的知识优先进入优化
- 与 §3.5 的关系：每个用例的"通过/失败"判断仍须遵守重复评测等可靠性约束

### 职责边界（只读原则）⭐

| 参与者 | 职责 | 是否允许修改知识 |
|--------|------|-----------------|
| **评测过程** | 运行 UT、统计通过率、计算置信度 | ❌ **只读**，不修改知识 |
| **coder agent** | 把知识库转成代码，**不承担迭代逻辑** | ❌ 不修改知识 |
| **知识飞轮** | 根据置信度迭代优化知识 | ✅ 允许 |
| **首次生成 agent** | 知识库的首次生成 | ✅ 允许 |

> 原则：**谁评测谁不改，谁生成谁可改**。评测与生成分离（依据：[critic.md](../research/feedback-loop/critic.md)）。
