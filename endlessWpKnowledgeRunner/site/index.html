WHY WPKNOWLEDGE

写得像答案，
不代表真的能用。

wpKnowledge 不只保存结论。它还记下结论怎么被验证、失败后改了哪里，以及最后是谁按规则放行。

未经行为验证CANDIDATE

看起来像答案

有结构、有来源、质量门禁通过，但还没有独立执行证据。它可以进入评测，不能直接进入正式查询结果。

  • — 文档质量 ≠ 行为正确
  • — Agent 自评分 ≠ 独立证据
  • — 单次成功 ≠ 稳定可复用
QUALITY
GATE

绑定固定来源、完整测试报告、工具链指纹和不可变工件，再由确定性 Gate 与原子事务完成发布。

ARCHITECTURE

一个核心，
多种入口。

TRUST BOUNDARY

有些事，
它现在还做不到。

01固定项目验收面向受信源码，不是敌对代码的 OS 沙箱。

02deterministic fixture 证明编排，不证明 live 模型质量。

03Web Console 默认只读，普通 Agent 没有自行发布权限。

04Publication Gate 只接受完整、匹配且可校验的独立证据。

05Agent 只能追加提示词；职责、输入输出、拓扑与工具权限不可替换。

GET STARTED

自己动手，或者交给 Agent。

两条路径做的是同一件事：装好依赖、跑完门禁、初始化本地 Registry，然后以只读模式打开 Console。

FOR PEOPLE

看着每一步跑完

需要 Git、Node.js 24+ 和 npm。命令结束后，浏览器打开本地 Console；新环境还没有 VERIFIED 知识时，查询为空是正常的。

完整快速上手 ↗ 贡献指南 ↗
bash · wpKnowledge 
git clone https://github.com/linlisWorkTeam/wpKnowledge.git
cd wpKnowledge
npm ci
npm run typecheck
npm run validate:specs
npm test
npm run knowledge -- init
npm run knowledge:serve
→ 打开 http://127.0.0.1:4174

FOR AGENTS

复制 Prompt，让 Agent 接手

这段 Prompt 会要求 Agent 保护现有改动、执行真实门禁、用独立运行目录启动服务，并把失败如实告诉你。

阅读 Prompt 说明 ↗ Spec 总入口 ↗
prompt · setup wpKnowledge 
请从 0 到 1 配置并启动 wpKnowledge。你需要实际执行命令、处理可安全修复的问题，并在最后给出可核对的结果。

仓库：https://github.com/linlisWorkTeam/wpKnowledge

执行要求：
1. 如果当前目录已经是 wpKnowledge，先检查 git status，保留所有未提交改动；否则克隆仓库并进入目录。不要覆盖用户文件。
2. 阅读 README.md、CONTRIBUTING.md、endlessWpKnowledgeRunner/docs/GETTING_STARTED.md 和 endlessWpKnowledgeRunner/specs/README.md。
3. 检查 Git、Node.js 和 npm。Node.js 必须是 24 或更高版本；版本不满足时，使用机器已有的版本管理器升级，并说明改了什么。
4. 执行 npm ci、npm run typecheck、npm run validate:specs、npm test。任何门禁失败都要先定位原因；不得跳过测试、降低阈值或伪造通过结果。
5. 使用独立运行目录初始化：
   WP_FLYWHEEL_HOME=.workpanel npm run knowledge -- init
   WP_FLYWHEEL_HOME=.workpanel npm run knowledge -- status
6. 以只读模式启动 Console：
   WP_FLYWHEEL_HOME=.workpanel npm run knowledge:serve
   检查 http://127.0.0.1:4174/health，并确认首页可访问。
7. 除非我明确要求公网访问，否则只监听 127.0.0.1。不要设置 WP_KNOWLEDGE_WRITE_TOKEN，不要把 token、数据库、CAS 或 .workpanel 提交到 Git。
8. 不得把 CANDIDATE 手工改成 VERIFIED，不得调用已退休的 score、eval 或 harvest，也不得把 deterministic fixture 写成 live 模型质量证明。
9. 最后报告：实际 Node/npm 版本、运行过的检查及结果、服务 PID、访问地址、运行目录、git status，以及仍未解决的问题。若服务无法启动，保留完整错误摘要并给出下一步。
