> 状态：Living gap analysis  
> 基线：2026-08-26，已包含远端提交 `8cfe6d2` 的新门禁实现。

## 1. 当前结论

当前代码已具备最小流水线、C/C++ 编译测试、基础修订、部分 sandbox、JSON holdout，以及至少 5 次重复评测的均值/方差/最差值与 UNSTABLE 判定，但尚未满足收敛设计的全部 P0 约束。尤其不能把 DeepSeek demo 一轮通过或桩测试通过当作生产合规证明。

## 3. 实施顺序

### P0-A：先修正裁判

1. **P0-A1 评测统计模型（部分完成）**：已计算 mean/variance/min 并默认 5 次；下一步保存每次结果、拆分重复生成/重复执行，并消除 `passed=max` 的歧义。
2. **P0-A2 统一门禁函数**：阈值只来自 Config；删除 `EvalReport.passed_gate` 的固定 0.8。
3. **P0-A3 状态机完备（部分完成）**：已加入 unstable；继续加入 invalid/stopped、零用例、预算耗尽和 reason codes。
4. **P0-A4 holdout 发布规则**：verified 与 pass 必须发生在 holdout 验证之后；native 需显式 holdout 或不可发布。

验收：ACC-EVAL-001~006、ACC-HOLD-001~003、ACC-FLOW-001。

### P0-B：收紧信息与写保护

1. **P0-B1 生产路径校验**：生产模式强制 interfaces_dir，禁止回退 src_dir。
2. **P0-B2 最小权限沙箱**：Coder 只读当前知识/接口和本轮目录；补 Windows、符号链接和前缀碰撞测试。
3. **P0-B3 评测集分区**：public 接口与 private expected/holdout 分离。
4. **P0-B4 写保护**：执行前后完整 SHA-256 比较，越权即失败。

验收：ACC-SEC-001~004、ACC-ROLE-002。

### P0-C：修正知识版本与审计

1. **P0-C1 候选区**：draft 写入 run artifacts，不直接污染已接受 knowledge。
2. **P0-C2 真回滚**：按 parent_version 和哈希恢复持久化内容。
3. **P0-C3 append-only ledger**：禁止 clear 丢历史。
4. **P0-C4 报告 v1**：run ID、配置快照、环境、commit、统计和 reason codes 完整落盘。

验收：ACC-KNOW-002~004、ACC-OBS-001~002。

### P0-D：接入生产模型

1. 抽象模型 provider，不把 API key、base URL 和模型名写死在角色实现。
2. 实现 GLM 5.1 / codeagent CLI 适配。
3. DeepSeek 仅保留在显式 `experimental` provider 下，README 不再称其为生产全流程。
4. 为三个角色记录模型、prompt 版本、输入文件清单和输出哈希。

验收：ACC-MOD-001、ACC-ROLE-001。

## 4. 暂不进入 P0

- AST/数据流相似度；
- 多候选 pass@k；
- 自动覆盖率与 mutation score；
- 语义保持变换和评测集轮换；
- 性能/内存门禁；
- 上亿行代码的全库切分与调度。

这些能力进入 P1/P2 时仍必须保持测试主判、角色分离、holdout 隔离和可回滚约束。
