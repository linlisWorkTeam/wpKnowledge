# 验收场景

> 状态：Normative acceptance  
> 每个场景都应最终落为自动化测试；当前映射见[追踪矩阵](06-追踪矩阵.md)。

## A. 门禁与统计

### ACC-EVAL-001 编译失败不能通过

**Given** Coder 生成无法通过配置编译器的代码  
**When** 自动评测执行该轮  
**Then** 测试不执行，decision 为 `iterate` 或预算耗尽时的 `stopped`，且报告含 `COMPILE_FAILED`。

### ACC-EVAL-002 测试是唯一主判

**Given** 两份生成代码的相似度不同但编译和测试结果相同  
**When** 状态机计算 decision  
**Then** 两者 decision 完全相同。

### ACC-EVAL-003 禁止取最大值

**Given** 5 次结果为 `1.0, 0.5, 1.0, 0.5, 1.0`  
**When** 生成评测报告  
**Then** 报告保留全部结果并计算 mean、variance、min，不得把 confidence 记录为 1.0 后丢弃波动。

### ACC-EVAL-004 不稳定结果不能通过

**Given** mean 达到通过阈值但 variance 超过配置上限  
**When** 状态机判定  
**Then** decision 为 `unstable`。

### ACC-EVAL-005 零用例失败关闭

**Given** 评测集没有当前模块的有效用例  
**When** 运行评测  
**Then** decision 为 `stopped`，reason 包含 `ZERO_CASES`，知识不得标为 verified。

### ACC-EVAL-006 阈值不写死

**Given** 相同报告分别使用阈值 0.8 与 0.95  
**When** 状态机判定  
**Then** decision 按配置变化；数据类属性和角色不得自行使用固定 0.8。

## B. train / holdout

### ACC-HOLD-001 holdout 不产生修订反馈

**Given** train 全过而 holdout 有失败  
**When** 执行最终验证  
**Then** 生成角色只能看到 holdout 未达标的聚合状态，看不到失败输入、期望输出和具体断言。

### ACC-HOLD-002 未执行 holdout 不得发布

**Given** 配置要求 holdout，而 native 评测格式无法划分 holdout  
**When** train 达到阈值  
**Then** 系统不得返回可发布的 `pass`；必须明确 `stopped` 或使用预先分离的 native holdout。

### ACC-HOLD-003 稳定分区

**Given** 相同模块、相同评测集版本和相同 split 配置  
**When** 多次构建 train/holdout  
**Then** 分区保持一致，且 manifest 能解释每条用例所属分区。

## C. 隔离与安全

### ACC-SEC-001 Coder 无法读取源码

**Given** `src_dir` 即使被加入 `allowed_read_dirs`  
**When** Coder 尝试直接路径、`..` 或符号链接读取源码  
**Then** 所有访问均以 `SOURCE_ACCESS_VIOLATION` 失败。

### ACC-SEC-002 生产配置必须有接口副本

**Given** 生产模式未配置 `interfaces_dir`  
**When** 创建 Coder 沙箱或启动 runner  
**Then** 配置校验失败，不得回退到 `src_dir`。

### ACC-SEC-003 最小权限工作区

**Given** `work_dir` 中存在上一轮报告、生成代码和 holdout 聚合  
**When** Coder 运行  
**Then** Coder 只能访问本轮输出目录，不得读取历史 artifacts。

### ACC-SEC-004 写保护发现越权修改

**Given** 角色执行前已记录受保护文件完整 SHA-256  
**When** 任一受保护文件被修改  
**Then** 执行后校验产生 `PROTECTION_MISMATCH`，本轮结果作废。

## D. 知识与修订

### ACC-KNOW-001 知识不泄露完整实现

**Given** 知识生成 Agent 可读取源码  
**When** 它生成提供给 Coder 的知识  
**Then** 文档包含签名、语义、算法步骤、边界和 sources，但不包含连续源码函数体或完整实现。

### ACC-KNOW-002 修订产生新版本

**Given** verified v2 与针对某段的 correction  
**When** 知识生成 Agent 修订  
**Then** 产生 draft v3，v2 内容和元数据保持不变。

### ACC-KNOW-003 回滚恢复真实内容

**Given** v3 指标低于已接受 v2  
**When** 状态机返回 rollback  
**Then** 当前版本恢复为持久化 v2 的内容、sources 和哈希，而不是只把 v3 的版本号减一。

### ACC-KNOW-004 修订历史不可丢

**Given** correction 从 pending 被处理  
**When** 它成功或失败  
**Then** ledger 保留其最终状态和证据；开始下一轮不会删除旧记录。

## E. 模型与角色

### ACC-MOD-001 生产模型受控

**Given** 生产模式配置  
**When** 创建三个角色  
**Then** 模型为公司 GLM 5.1 且走批准的 codeagent/SDK 适配；DeepSeek 配置只能在显式实验模式启用。

### ACC-ROLE-001 Review 不能改客观结果

**Given** 自动报告 confidence 为 0.6  
**When** Review 输出“建议通过”  
**Then** 状态机忽略该主观判词，按客观报告和阈值决策。

### ACC-ROLE-002 只有知识生成 Agent 可写知识

**Given** Coder、Review 或 Evaluator 尝试写入知识目录  
**When** 写保护和权限校验执行  
**Then** 操作被拒绝并记录安全事件。

## F. 有界执行与审计

### ACC-FLOW-001 达到上限明确停止

**Given** 连续多轮未达到门禁，且达到 max rounds / time / cost 任一上限  
**When** 编排层收口  
**Then** decision 为 `stopped`，报告原因和最佳已接受版本，不得把最后一轮误标 verified。

### ACC-OBS-001 运行可追溯

**Given** 一次包含两轮修订的运行  
**When** 运行结束  
**Then** 同一 run ID 下可找到配置快照、两个知识版本、两份代码、两份 train 报告、归因、修订记录、保护校验和最终结果。

### ACC-OBS-002 未执行不等于通过

**Given** 环境缺少 pytest、编译器或模型凭据  
**When** 执行验收  
**Then** 结果明确记录 skipped/blocked 及原因，不得报告“全部通过”。
