# 行为与数据契约

> 状态：Normative contracts

## 1. 角色接口

### 1.1 KnowledgeGenAgent

```text
generate(module, source_snapshot, source_refs) -> KnowledgeCandidate
revise(candidate, corrections) -> KnowledgeCandidate
```

前置条件：源码快照只对该角色可见。  
后置条件：输出是新知识候选，包含稳定 sources；不包含完整源码函数体。  
失败：模型空输出、sources 缺失、知识泄露检测失败或超出资源上限时必须显式失败。

### 1.2 CoderAgent

```text
generate_code(knowledge_candidate, task, interface_bundle, output_path) -> CodeArtifact
```

前置条件：输入目录通过沙箱最小权限校验。  
后置条件：只产生代码产物，不修改知识、评测集或历史报告。  
失败：输出为空、不是可识别代码、试图越权访问或上下文不完整时显式失败。

### 1.3 ReviewAgent

```text
attribute(knowledge_candidate, public_eval_report) -> AttributionReport
```

Review 读取的是脱敏后的客观失败信息，不读取 holdout 详情。输出 corrections 必须包含：

```json
{
  "id": "parser-empty-001",
  "knowledge_path": "parser.md#空输入",
  "criterion": "case parser-empty-001 passes",
  "detail": "补充空输入返回默认值的行为说明"
}
```

## 2. 自动评测契约

### 2.1 编译

- 使用项目配置的编译器和 flags；生产运行必须记录真实命令与版本。
- `-Wall -Werror` 是无既有工程约定时的最低默认值。
- 编译失败后 `compile.passed = false`，测试统计不得伪造为已执行。

### 2.2 重复测试统计

每次重复独立记录：

```text
confidence_i = passed_i / total_i
mean = arithmetic_mean(confidence_i)
variance = population_variance(confidence_i)
min = minimum(confidence_i)
```

约束：

- 每次的 total 必须一致，否则报告无效。
- 不得只保留最大 passed。
- 默认建议 `repeat_eval >= 5`；若为确定性二进制重复执行，应把“重复生成”和“重复运行”分开记录，不能用重复运行替代 LLM 多次生成。
- 门禁使用哪一统计量必须配置化并在报告中明确；未完成 PoC 校准前，不得假设最佳值或单次值。

### 2.3 相似度

```text
diagnostics.similarity = optional
```

状态机不得读取该字段决定 pass、iterate 或 rollback。删除该字段应不改变同一测试结果的 decision。

## 3. 门禁决策契约

输入：编译结果、重复评测统计、阈值、稳定性阈值、已接受基线和资源上限。  
输出：`pass | iterate | rollback | unstable | stopped`。

建议判定顺序：

1. 评测无效（零用例、统计缺失、环境失败）→ `stopped`。
2. 编译失败 → 尚有预算则 `iterate`，否则 `stopped`。
3. 方差超限 → `unstable`。
4. 指标低于已接受基线 → `rollback`。
5. train 未达阈值 → 尚有预算则 `iterate`，否则 `stopped`。
6. train 达标但 holdout 未执行或不合格 → 不得发布为 `pass`。
7. train 与所需 holdout 均达标 → `pass`。

## 5. Correction Ledger v1

使用 append-only JSONL 或等价不可丢历史存储：

```json
{
  "schema_version": "correction.v1",
  "run_id": "...",
  "round": 1,
  "id": "tiling-tail-001",
  "knowledge_version": 1,
  "knowledge_path": "tiling.md#尾核处理",
  "criterion": "all tail cases pass",
  "detail": "补充最后一个核的尾块计算",
  "status": "pending | done | failed",
  "evidence": ["eval/train_round_001.json"]
}
```

`clear()` 不得删除审计历史；它只能关闭当前活动队列或建立新 run。

## 6. 错误语义

| 错误码 | 含义 | 默认处理 |
|---|---|---|
| `SOURCE_ACCESS_VIOLATION` | Coder 触达源码区 | 立即停止，安全失败 |
| `HOLDOUT_LEAK` | holdout 详情进入生成上下文 | 立即停止，本次结果作废 |
| `EMPTY_MODEL_OUTPUT` | 模型返回空内容 | 有限重试后停止 |
| `INCOMPLETE_CONTEXT` | 输入被截断或缺少必要知识 | 请求补齐或停止，不臆造 |
| `COMPILE_FAILED` | 生成代码不可构建 | 进入归因/迭代 |
| `ZERO_CASES` | 没有有效测试用例 | 停止，不能通过 |
| `UNSTABLE_RESULT` | 重复结果方差超限 | unstable，不通过 |
| `REGRESSION` | 主指标低于已接受基线 | 回滚到持久化基线 |
| `MAX_BUDGET` | 轮次、时间或成本耗尽 | stopped，报告未收敛 |
| `PROTECTION_MISMATCH` | 受保护文件哈希变化 | 立即停止，安全失败 |

## 7. 配置约束

生产配置至少包含：

- 显式 `src_dir` 与 `interfaces_dir`，二者不得相同或互为父子；
- 私有评测集目录与公开接口目录；
- `pass_threshold`、`variance_threshold`、`repeat_generation`、`repeat_execution`；
- `max_rounds`、超时和成本上限；
- 模型 ID、接入方式和 prompt 版本；
- 运行产物根目录与受保护路径列表。

配置加载时必须 fail fast；不能用不安全回退让生产运行继续。
